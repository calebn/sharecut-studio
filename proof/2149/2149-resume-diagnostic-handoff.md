## What each measurement separates

- Trusted touchstart/end targets, changedTouches/active touches and native timestamps distinguish one-contact released double taps from wrong target, incomplete release or multi-contact input. `elementFromPoint` is logged with client coordinates as reported, without guessed scale corrections.
- Event composed paths include SVG/path/span descendants and computed touch-action/overflow/transform through ancestors. This distinguishes actual hit policy/scroll ancestry from merely reading the button's CSS after the fact. It does not itself establish Safari's internal touch-action decision.
- Stable WeakMap nodeIDs, connected flags, buttonrects, active classes/aria-pressed and nav mutation records distinguish stable same-tab DOM from mode-change replacement, movement, or a second tap landing on a descendant/overlay. Keys in source suggest stable nodes, but runtime must confirm.
- Capture/bubble and explicitly named capture-microtask defaultPrevented/cancelable observations locate observable event consumption. A capture microtask may run between native event listeners; it is NOT final defaultPrevented or guaranteed after-dispatch evidence. Missing bubble alone may reflect propagation; it is not proof default was cancelled. All probe listeners are passive. The HTML callback cleanup can perform a microtask checkpoint when the JS stack empties: https://html.spec.whatwg.org/multipage/webappapis.html#clean-up-after-running-a-callback .
- visualViewport scale/width/offset events versus layout/client/scrollwidth and timeline scroll metrics separate page magnification/pan from layout overflow and timeline rendering. No app store monkeypatch or state getter is introduced; use existing QA appzoom measurement if available and record its source separately.
- An already-selected Timeline failure with identical connected DOM/rect and no observed mode change would reduce the mode-replacement hypothesis. The button still dispatches its command; unchanged aria-pressed does not prove absence of a command or all app-state changes. Independent appzoom measurement remains required, otherwise appzoom is unknown. A failure only while switching warrants focused command/DOM tracing next. These are hypotheses, not conclusions before receipt inspection.
