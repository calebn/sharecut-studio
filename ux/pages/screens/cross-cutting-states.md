## Cross-cutting states

| State | Where surfaced |
|-------|----------------|
| **Loading record room** | `/rec/{token}` before the room lookup returns: the Room shell with grey placeholders for the title and four tiles and a dimmed, inert dock appears at once (no 300 ms blank, no "Loading studio…"); at 4 s “Still connecting…” with Retry joins the alert slot and Retry looks the room up again. See Guest / record › Loading |
| **Pending edits** | Host Review queue · chips · edit overlay · inspector (guests: Timeline/inspector, not the queue) |
| **Mix out of date** | A guest never sees it, because a guest's payload carries no premix freshness, so the check would flag it falsely and the guest could not act on it (a guest can still play a range while the live project is stale); a guest sees only **No mix yet** when Play finds no mix, or why Play cannot start. Player bar mix ring (reads **Mix out of date**, or **No mix yet** when nothing is rendered; the host's mix rebuilds on its own and the pill reads **Updating mix** meanwhile; Refresh mix in the palette updates it now); the mix ring’s tooltip is the same text. On an edit share, Refresh mix starts a host job immediately; the guest waits on token-scoped status reads, then hears the refreshed mix or sees a failure. While another render holds the lock, a rerender request plays the previous render (the audio response carries `X-Sharecut-Render-Busy: 1`, which the Player bar does not read yet; the Mix out of date chip stays because the stem was not rebuilt). |
| **Transcript stale / reconcile** | Stage bar **Reconcile** badge · Script affordances |
| **Pipeline / activity running** | Prepare lists pipeline jobs in the summary. While bounce/export/`render_preview` occupy the shared pipeline-slot, Run is disabled and Cancel is in Prepare. The Prepare badge and Player status show the most recent live job (`status-pipeline` chrome: truncated headline, dim **stale “last update Ns ago”** companion, elapsed, pulse; phone chip ellipsizes overflow). Guests also see the chip in Review (non-interactive — Prepare is host-only). Non-pipeline kinds (`agent` from in-process host MCP, `bounce`, `export`, `render_preview`, guest remote MCP) use **Activity** copy; a count badge (“2 activities”) when more than one job is live. Chip/Listen open Prepare only for slot jobs; agent chips are not a navigation target. Instant tools never flash a chip. A host job that failed for a model that is not downloaded shows **Download {model}** beside the chip (status bar, phone Listen) and under Prepare's error; it opens the model prompt only when pressed, and a failed Refresh mix resumes once after it. |
| **Loading episode** | `?project=` known, shell not yet (HTTP or document WS): DAW grid/skeleton chrome (“Loading episode…”). Distinct from the zero-track Start tiles. A shell load the server never answers (30 s) shows the stage-body cover “Could not load the project. The server didn't answer.” (Review: “The transcript didn't load”) with Try again, on Chromium and WebKit; the button stays, busy, while the retry runs. A warm shell reload that times out while the episode is already open (for example a long Approve all) retries silently with the episode on screen (up to ten retries, three seconds apart); if every try fails the stage body shows the same failure cover. After shell, live edits update the visible document while compatible word chips remain hydrated |
| **Result toast** | Every status message (“Reordered track”, “Removed guest”, “Mix preview refreshed”, export results) shows as one toast, centred above the Player bar on desktop and tablet. On a phone it sits just above whatever is docked at the bottom (an open sheet, the Edit tool strip, the tab bar) and below the header; on a short phone it moves above the Player's Play button, never over it. On every screen size it stays off the comment field, the **Commenting as** line and the name field: it moves above or below them, and in a window too short for a free band it covers the content above them instead. A visible compact inspector places feedback first inside the same bounded body scroller as its fields, below the pinned header. The focused or just-pressed control keeps its place when feedback arrives. At large text sizes ordinary body scroll exposes feedback or a full native label separately; field focus reveals the control and its complete label below the pinned header when it fits. Compact half and full detents keep the same outer height with or without the card. Dismiss removes it without changing detent height or lane room. One card pauses expiry while clipped and retains its remaining visible time across floating and inspector hosts. Keeping every visible control clear remains a beta requirement; screen readers hear the same words, even when the same message repeats. **Undo** appears on every edit the toast reports (delete, cut, paste, trim, fade, chapter and envelope point add, track reorder and removal, Review cuts and keeps and Apply suggested actions) and disappears once anything else moves history; while an edit is still saving it says “Undo ready after save”, and a press waits for the save and runs only if the change is still the latest step (otherwise it says nothing was undone). Dismiss closes it; it closes after 6 s of unpaused visible time (10 s when it offers Undo). Job progress stays on the job chip, presence joins on the avatars and the Needs attention summary on its banner, so they don't toast. **Resolved comment** uses the same toast, and its Undo reopens the comment. A failure reads in an error look that names what failed and the next step. A Fix text save that fails after leaving Script shows its reason once as an error toast if the same project is still open, without changing a newly opened draft. A refusal while its editor remains open stays inline; a failure from an earlier project opening is not shown. A message about a gesture, such as an armed clip, leaves when the finger lifts or the mode changes. |
| **Confirm / ask dialog** | Actions that discard work ask first in the app's own dialog (a bottom sheet on phone): the question names the target, one line gives the consequence, **Keep** comes first and focused, the action comes last (red only when it cannot be undone). Find hits again uses it. Removing a track and replacing a track's audio do not ask: each shows a toast with Undo. When the file picker is unavailable, Open project asks for the path in the same dialog, with the error under the field. Escape closes only the dialog: the Inspector or sheet behind it stays open, and focus returns to the button that asked. There are no browser pop-ups. |
| **Offline host (relay)** | Share/tunnel offline page |
| **Offline edit queue** | Host and guest edits wait offline and drain on reconnect; guest structural ops demote to propose. Pending drag and mixer values stay visible while peer edits arrive. Replaying an older queued value does not replace a newer pending value. |
| **Offline attention** | Host pending count and host/guest conflicts appear in **Needs attention**; conflicts are dismissible |
| **Presence** | Header **avatar stack** (follow/unfollow, each avatar titled "Follow `<name>`" / "Stop following `<name>`"); ghost cursors on timeline lanes and DAW chrome (`data-presence-anchor`); unresolved anchors hidden. Follow mirrors tab/transcript/audition/selection when capable. Header avatars (names in the tooltip; the phone shows one avatar plus a count, and tapping it opens a menu with the rest). Following is shown by the header "Following {name}" pill (its tooltip and status text carry the guest Mix / host-only tab hints) and a thicker avatar ring; the Player keeps a pill only for a partial follow. Phone Review = listen-along; phone Timeline = colored center needle (not a copied zoom window). Follower count only; followers do not broadcast a lagging playhead. Guests never draw their own cursor. A remote playhead is a thin line from the ruler to the bottom of the last lane (not into the empty space below it), with a flag on the ruler. Remote playhead ghosts move between presence frames at the leader’s rate, hold when paused, and clamp to the session length. Follow corrects local audio drift on a timer. Leaders send playback updates once per second and immediately on play, pause, seek, or rate changes. Invalid positions are ignored. The server drops an invalid presence playhead and keeps the last good one. Roster names (tooltip, More → People, avatars) are cleaned on the server: control characters are dropped, names are capped at 40 characters, and a guest named "Host" shows as "Host (guest)". |
