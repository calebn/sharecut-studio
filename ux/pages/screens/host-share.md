## Host: Invite sheet (every stage) and the Deliver Listen link

| | |
|--|--|
| **Purpose** | Manage review links, record-room guest / producer invites and the listen link for the open episode from one sheet |
| **Open** | Header **Invite** on every stage, Project → Share…, and the Record stage's empty Person tile, Record **More** → **Invite and links…** (these open it at **Record links**) all open the Invite sheet over the current stage (`share.manage`, optional `at: record`; collaboration extension slot `share.ui.menu`). Header Invite is hidden for Viewer and Commenter guests. A centered sheet on desktop and tablet, a bottom sheet on a phone |
| **Groups** | **Review links**, **Record links**, **Listen link**, in that order. Each Review and Listen group opens with a ready Link row at its default (Review: Commenter, following the latest version; Listen: Viewer, pinned to the version current when you copy it). There is no Create button: the link is made and copied on the row's first **Copy** |
| **Link row** | Role chip (a Viewer / Commenter / Editor choice while the review link is not made yet), the link in mono cut in the middle, a globe glyph (filled: reachable from anywhere; slashed: only on this network) that opens a one-sentence popover, who opened it with a count, a **Pin to this version** toggle (on: frozen on this version; off: follows the latest; set before the link is made and shown read-only after), **Copy** and **More**. More holds **Allow AI assistants** (a setting before the link is made, **Copy MCP URL** after) and **Stop sharing**, which acts at once and raises an Undo toast. The QR code, **Replace link** on a review link and changing the pin of a made link are not built: they need a backend that does not exist yet |
| **Record links** | Each record room with its guest and producer links, Copy for each, **Replace** for a closed invite, **End room** (disabled with its reason shown while a take is running or not on the timeline yet, or before the Record state is known; asks first when someone is connected; otherwise acts at once, with an Undo toast). A room whose open links only work on this network shows one note under its links: “Online sharing is off, so only people on this network can open these links.” when online sharing is off, or “Online sharing isn't set up on this computer, so only people on this network can open these links.” otherwise, then “Turn on online sharing to invite anyone.” and a **How to turn on online sharing** guide link; Copy keeps copying and is described by the note. No note when online sharing is connecting, online, limited, reconnecting or unavailable, for a public address with no online sharing feature, or when every invite in the room is closed. **Create record links** and, once, **Open Record stage** under the rooms (only when at least one room exists, the sheet is over another stage and the Record stage is available; disabled while a share action is running; it closes the sheet and, like Mod+1, stops following). “No record rooms yet.” when there are none |
| **Data shown** | Online sharing line at the top (when the `tunnel.status` feature is present): “Guests can open your links”, “Connecting…”, “Reconnecting… guests may see a brief interruption” with a “Trying again in N s” countdown (a still clock time under reduced motion), “Not reachable online: guests can't open links until you're back online” with a **How to fix** disclosure and guide link, “Online sharing is off” with **How to turn it on**, “Online sharing is limited: some links may not open for guests” or “Online sharing is unavailable right now.”; no line on a local-only host (each Record room card carries the note above instead). Limited and unavailable are described in the next paragraph. Each review link by its role with its review mix label, “AI assistants allowed” when it has an MCP URL, and its dates |
| **Empty / error** | A project with no mix yet turns the row that asked into “Make a mix to share” with **Refresh mix** and the message “This project has no mix yet. Refresh the mix to create the link.”; a stale preview gets the same row and a friendly alert, and after a successful render the create is retried once. A stale master explains that a new master is needed and does not offer preview refresh. If the browser refuses the copy the button reads “Press Ctrl C” with the whole link selected |
| **Out of scope** | Restricted ACL; expiry picker (links never expire until the host stops sharing; `expires_at` stays on the CLI and MCP); in-place review-role edit (rotate = new link + stop old); guest share-token MCP UI |

**When online sharing is limited or unavailable.** The sharing service holds each computer to a few live links and a monthly allowance of traffic, so an abused service cannot be used up by a few computers. Two limits show on the online sharing line, with the connection still up and no countdown, because trying again changes nothing. Past the number of links one computer may keep open, “Online sharing is limited: some links may not open for guests” opens to **How to fix**: “Only a few links can be open online at once. Turn off links you no longer need, then start online sharing again.” The links that fit keep working. Once the month's allowance is used, the same headline opens to “Your links have used this month's online sharing allowance. Guests can open them again next month.”, and a guest who opens one of the links sees “This link is paused for now” until the month turns. The line clears by itself when the limit lifts. If the service has switched online sharing off for this computer, the line reads “Online sharing is unavailable right now.” with **Contact support or report this** under it, which opens the support page the Help dialog uses (the same link, so a distribution that sets its own support address shows it here too). That state is final until the host reports it, so it shows no countdown and no **How to fix**. A guest of a switched-off computer sees the host-offline page. If the sharing service address in the settings cannot be used to set up online sharing (a service that is not set up for it, or one that needs updating), the line is the offline one, “Not reachable online: guests can't open links until you're back online”, and **How to fix** reads “The sharing service address in your settings looks wrong. Correct it, then start online sharing again.” When a computer that has signed in before gets "not found" back, it keeps its current sign-in and retries quietly. Only after three "not found" answers in a row over at least five minutes (or when the service had already refused its sign-in, or the sign-in is expired or about to expire) does **How to fix** read “Your sharing service looks older than this version of ShareCut. Ask whoever runs it to update it, or check the address in your settings.” A computer that is still connected sees it only when the connection next drops, and from then on it stays offline until the settings change. None of these lines says tunnel, relay, lease or token.

**End room** follows the gate End session uses. It is disabled, with the reason in a note under it, while the Record stage's room has a running or paused take (“Stop the take first.”), a take not yet on the timeline (“Wait for every take to reach the timeline before ending the room.”) or live comments not landed, and for every room while the Record state is unknown (“Open Record to check this room before ending it.”). When someone besides the host is connected it asks in place: “End the room? Ava is sent out.” (two names, then “and others”; nobody named: “Everyone in it is sent out.”) with **Keep room** focused and **End room**; Escape keeps the room and leaves the sheet open. Both buttons are 44 px on touch. After an end, and after its Undo, the Record stage looks the room up again and shows “No record room yet” or the restored room without a reload.

**Stop sharing** and **End room** (when it acts) act at once. The toast says “Link stopped.” or “Room ended.” and offers **Undo** even if Invite closes while the request runs. The toast leaves half a second before the server's 10-second restore window closes, including when hovered or focused. While Undo is available, confirmations for creating or copying links appear in the share status line. A second Stop sharing or End room says “Undo is still available.” and leaves the second link or room live.

**Undo** restores the same link or room and says “Link restored.” or “Room restored.” The toast explains a server refusal. If the request fails with time left, you can try the same Undo again. The button is reachable by keyboard and 44 px on touch. When the refreshed list removes the link or room, focus moves from the removed control to its heading in Invite or Deliver. When Undo finishes, focus returns to that heading if focus was lost or stayed in the toast and the heading is still available.

If Invite warns that earlier links may still work, the new room is ready. Use
**End room** on earlier rooms. Creating another room may end the one you just created.

If the command line warns that earlier links may still work, the new room is ready.
Use the warning’s recovery commands to end earlier rooms without creating another room.

**Deliver** keeps only the **Listen link** row, in the right column after the Episode file (phone: after the Episode file, before Chapters), with the same behavior as the sheet's Listen group. After Deliver confirms that a Project default export matches the current settings and episode, **Copy** is outlined as the follow-up. While the settings check is unavailable, the successful export still shows its summary and files and **Copy** keeps its usual appearance. A one-off named loudness export keeps the existing Listen link. Export stays the only filled button until a file exists, then Reveal or Download takes over. The design system drops the old ⌘⇧C chord, so Copy listen link has no key and no palette command; the row's **Copy** is the way.

In Deliver, a selected audio format that becomes unavailable stays checked and
removable in Episode file, without a size estimate. Export and Feed repair wait
until that choice is restored or removed. It cannot make an earlier export
current by silently dropping the missing format. Once compatible choices return,
Deliver checks current settings again before highlighting the Listen link.

When a participant is removed, the Record stage directs the host to **Copy
links…**. The Invite sheet marks the affected role's invite closed to new guests, disables
copying its old link, and offers a same-room, same-role replacement. Existing
leases remain valid. If the removed guest's link cannot be identified, both
invites show as closed and a replacement is refused with “Start a new room”:
**Start new room** is the only way to reopen them. Guests never see the sheet (`canManageProjects` is false
on `share:{token}`).

Storybook `Stages/Frame/InviteSheet` previews the sheet with fictional links and `System/LinkRow` the row states; `Stages/Deliver/Deliver` the Listen link row in Deliver.
