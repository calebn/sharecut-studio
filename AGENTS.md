# Agent instructions

All changes to this repo must follow **SOLID** and **DRY**, include **tests as you go**, and keep **docs in sync** with the code.

## Git workflow

Ship via **feature branch → PR → `main`**. Do not commit or push directly to `main` unless the user explicitly overrides.

1. Update local `main` (`git checkout main && git pull`).
2. Create a branch: `type/short-kebab-description`.
3. Implement with tests and docs in the same change.
4. When the user asks to ship: commit on the branch, `git push -u origin HEAD`, `gh pr create` targeting **`main`**. Put `Fixes #N` (or `Closes` / `Resolves`) in the PR body so merge into `main` auto-closes linked issues, and `Related #N` for issues the PR touches but does not close (including review follow-ups).
5. Merge with **rebase** (`gh pr merge --rebase`), not squash, so `main` keeps each focused commit; keep branch commits conventional and self-contained. Merge only when the user asks. Exception: the `issue-pipeline` workflow (`.claude/workflows/issue-pipeline.js`) is pre-approved to rebase-merge its own PRs when its merge gate passes — see [docs/contributing.md § Automated issue pipeline](docs/contributing.md#automated-issue-pipeline).

Before working a GitHub issue, follow [.agents/rules/issue-claims.md](.agents/rules/issue-claims.md): skip issues with a live claim, claim before starting, move `pipeline:*` stage labels, and release when done.

`make hooks` (also run by `./install.sh`) points `core.hooksPath` at `.githooks`, which runs lint-staged (Ruff + Biome write and restage) then the check-only pre-commit hooks (via `pre-commit`, or `uvx pre-commit` when it is not installed). In a new worktree, run `make worktree-setup` (hooks + venv with CI extras + `gui/web` node_modules); the pre-commit hook runs it automatically when `.venv` or `node_modules` is missing. Do not add format-write hooks to `.pre-commit-config.yaml`.

**CI gate:** GitHub Actions runs the required full suite on public pushes and pull requests. `.githooks` has no pre-push full-CI gate; `make ci` is an optional local mirror. Detail: [docs/testing.md § GitHub CI gate](docs/testing.md#github-ci-gate), [docs/contributing.md § Git workflow](docs/contributing.md#git-workflow).

| Prefix      | Use                                          |
| ----------- | -------------------------------------------- |
| `feat/`     | New behavior                                 |
| `fix/`      | Bug fix                                      |
| `docs/`     | Documentation / agent instructions only      |
| `chore/`    | Tooling, deps, housekeeping                  |
| `refactor/` | Internal restructure without behavior change |
| `test/`     | Tests only                                   |

Examples: `feat/guest-sign-in-ui`, `fix/share-acl-401`, `docs/agent-pr-workflow`.

## SOLID / DRY (short)

1. **Single responsibility** — Business logic in `edits/`, `clips/`, `pipeline/`, `engines/`. Orchestration in `services/`. CLI/MCP/GUI only parse args and format output.
2. **Don't repeat yourself** — Use `ProjectWorkspace`, `run_mutation`, `util/review`, `project_io`, `export/transcript`. Never copy project load/save or history wiring into a new tool. GUI audio/pipeline must call `PlayService` / `PipelineService` (same as CLI), not reimplement artifact paths.
3. **Extend, don't fork** — New MCP tools: handler in `mcp/tools/`, register in `register_all`, re-export from `mcp/server.py` if tests need it. New CLI: add to `cli/<area>.py`. New GUI routes: thin handlers in `gui/server.py` over services.
4. **Stable MCP names** — Do not rename existing MCP tools without updating `.agents/skills/` and docs.

## Tests as you go

1. Add or update tests in `tests/` **in the same change** as the feature or fix. For Sharecut Studio UI under `gui/web/`, add Vitest tests (and axe checks for shared `ui/` / shells) and run `make test-web`. Full-page axe lives in Playwright (`make test-web-e2e`); do not silence a11y or other lint with ignore comments — fix markup/styles or get **explicit user approval** before any `*-disable` / `biome-ignore`. Use native controls and shared helpers (`src/test/a11y.ts`, `e2e/axe.ts`). Theme colors, space, and type belong in `gui/web/src/styles/theme/` (and `deploy/brand/brand-tokens.css`); partials and inline styles use `var(--…)` only. Chrome is rem + named `@container`; canvas `px` / `!important` / `@layer` need `-- user-approved:` Stylelint disables (Stylelint + `tests/test_css_policy.py`). See [.agents/rules/gui-styling.md](.agents/rules/gui-styling.md).
2. Run `make lint-py` / `make format-py-check` / `make typecheck` and `make test` before finishing; coverage must stay **≥95%** (`pyproject.toml`). Python uses Ruff (lint+format), Bandit, Vulture, Deptry, and mypy — do not add `# noqa` / `# nosec` without **explicit user approval**. `make test` runs in parallel (`pytest -n auto`); use `make test-fast` for a quick no-coverage inner loop. When changing `gui/web/`, also run `make test-web` (lint + format:check + typecheck + vitest + build; required in CI). For viewer shell / launch / axe / cross-browser regressions, run `make test-web-e2e` (Chromium suite + Chromium/WebKit compat matrix in `gui/web/e2e-compat/`). When changing `gui/desktop/`, run `make test-desktop` (sidecar launcher fmt/clippy/`rustc --test` + rustfmt + clippy `--lib` + lib tests; optional Rust toolchain). Local stand-in for all required CI jobs: `make ci` (desktop remains path-filtered / optional).
3. Prefer unit tests on domain/services; use existing patterns (`test_services.py`, `test_project_io.py`, `test_mcp_tools.py`).
4. Undoable mutations must go through `ProjectWorkspace.mutate()` (see `test_history.py`).
