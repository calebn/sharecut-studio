# GUI viewer

The read-only DAW viewer and the Studio frontend behind it: launch, frontend foundation, HTTP and WebSocket routes, decisions, timeline layers and frontend internals. [gui-integration.md](gui-integration.md) keeps the adapter contracts (clocks, undo, progress, editing flows) that CLI, MCP and GUI share.

Local web UI for inspecting and editing an episode. Editing is described in [daw-editing.md](daw-editing.md).

## Frontend foundation

ShareCut Studio (`gui/web/`) uses plain CSS + React (no Tailwind/shadcn). Semantic theme tokens live in `gui/web/src/styles/theme/` (light/dark via `data-theme` + `prefers-color-scheme`; transport toggle + `localStorage`). Shared chrome is the **ShareCut Studio UI library** under `gui/web/src/ui/` (Button, CommandButton, Dialog, Menu, Field, …) — charter and command-bus bridge: [`gui/web/docs/ui-library.md`](../gui/web/docs/ui-library.md). Comment UI is shared from `gui/web/src/comments/`. Domain CSS is split into `@import` partials from `gui/web/src/styles/daw.css`. See [`gui/web/README.md`](../gui/web/README.md).

## Launch

`services.app` owns the shared CLI/MCP viewer launch path. Host binding auth lives in `services.session_sync`; GUI routes keep the FastAPI request wrappers.

```bash
uv sync --extra gui
cd gui/web && npm install && npm run build && cd ../..
podcast gui --project /path/to/episode.sharecut
```

`python -m podcast_mcp.gui.serve --project` adopts the retired entry file and refuses a failed rename with the same coded error as `podcast gui`.

When the web build is missing (a source tree before `npm run build`, or a wheel built without it), `podcast gui` prints one startup warning, `GET /` returns a 503 HTML page with the build steps, and `open_gui_tool` returns `static_built: false` with the same text as `hint`; the API and `/mcp` keep working. See [setup.md](setup.md#web-build-in-wheels).

First-run setup checks FFmpeg readiness and downloads model assets only. When a required model is missing, Home shows one **Setup card** (`gui/web/src/stages/home/SetupCard.tsx`, "Get ShareCut ready", between the Source tiles and Recent): **Get ready** sends one run for every model that is not installed, the word aligner and speaker model included (the card names the size in words, "about 2 GB" with the default Whisper size), **Choose…** opens the **Models** sheet (`ModelsSheet`, a modal 420 px side sheet on the right of a desktop, a full-height bottom sheet on a phone) with one Model need row per capability (`gui/web/src/models/ModelNeedRow.tsx`: Transcription, Word timing, Speaker split, Noise reduction, each with its size and state in the meta line, and Get, a progress ring with cancel, or a **More** menu with **Update** and **Remove** for out-of-date models or **Remove** for installed models; no Apply), and the card's more menu has **Not now**, which hides it until the next launch of this tab or app window (`sessionStorage` key `sharecut.setup.notNow`; **Models** stays under the app menu's **Settings**). Nothing downloads until **Get ready**, **Get**, **Update**, or **Try again** is selected. While a download runs the card shows one bar with the bytes so far and the time left ("1.1 GB of 2.0 GB · about 3 min", once a few seconds have shown a rate) and an x icon button (40 px, **Cancel the download**); while the first status is on its way the card draws nothing for 300 ms and then static grey blocks; a failed download reads "The download didn't finish." with **Try again**, and a status that cannot be read reads "Couldn't check what's installed." with **Try again**, never the raw error. Missing audio tools (FFmpeg) are their own Setup card state, shown even when every model is installed and after **Not now**: "Audio tools are missing." with **Check again** and a link to the audio-tools setup guide, and no download; **Import audio**, a drop and **Record** then say the tools are missing instead of starting an episode. A device that cannot have audio tools (the status reports `tools.ffmpeg` as `unsupported`; see [setup.md](setup.md)) gets a third state, "Audio tools" with the server's one sentence ("ShareCut can't process audio on this device yet."), also shown after **Not now**, with no button, link or spinner, on the `unavailable` status row (a neutral ban mark and the hidden name "Not available", never the open circle of "not yet"); **Import audio**, a drop and **Record** show the same sentence. In the Models sheet that sentence is shown once at the top and each model row reads "Not available" with no **Get**, **Try again** or Whisper size control; a need row inside a step shows the server's sentence for that model with no **Get**. The web app never shows a download for a row the server reports as `unsupported` (`ModelState` kind `unsupported`, `gui/web/src/models/`). On a host that cannot process audio the engine reports every model row `unsupported` with that same sentence (`model_status`: RNNoise runs through FFmpeg and the word aligner and speaker model need the transcription stack that host also lacks), so no row offers an install. The web tests and stories read that payload from `tests/fixtures/bootstrap_status/unsupported.json`, captured from the real `/api/bootstrap/status` route under the iOS row; `scripts/export_bootstrap_unsupported.py` rewrites it and `--check` (in `make generated-check`) fails when the engine's answer changes.

On **loopback**, `--project` is optional: omitting it serves the host **home** (`gui/web/src/stages/home/HomeScreen.tsx` around `HomeView`): the **Import audio** and **Record** tiles over **Recent** (the last 20 episodes opened here, from `GET /api/projects/recent`; a card opens its project on the stage its chip names, a card whose folder moved offers **Find…**), **Open other…** (the OS folder picker, or a path field in a browser with none), and the app menu: the ShareCut wordmark opens **Settings** (Appearance, Saved in, Models, Keyboard shortcuts), **Connect agent** and **Help**, the same rows the Project menu ends with inside a project, so Home has no Help or More button of its own. Home binds Mod+I (Import audio), R (Record), Mod+O (Open other…) and ? (the command palette, as inside a project: `CommandPalette scope="home"` mounts it on Home, lists only the catalog commands marked `home` (**Report a problem…**, **Guides**, **Manage models…**, **Connect agent…**, **Open project…**, plus the Projects group) and opens on its Help group; **Help** in the app menu (on Home and in a project) opens the Help sheet with three rows: **Shortcuts and gestures** (closes the sheet and opens this palette), **Report a problem** (steps inside the same sheet to the diagnostics report, with **Back** beside the title; each step change is announced in a polite live region) and **Guides** (opens the documentation site in a new tab). On a desktop it is a 320 px popover under the menu button, on a phone or tablet a sheet. **Settings** (`gui/web/src/settings/`, command `settings.open`, host only; a guest's link has Appearance in its own menu) is a modal 420 px side sheet on a desktop or tablet and a bottom sheet as tall as its rows on a phone, with rows that act as they change: **Appearance** (System, Light, Dark; the same preference as the Project menu's Appearance row, kept in `localStorage` key `daw_theme`), **Saved in** (inside a project only: the folder that holds the project file, with **Reveal in folder** in the desktop app only, which calls `POST /api/project/reveal`, and **Move…** in the desktop app only: the host's folder dialog (`POST /api/project/pick-folder`; Cancel changes nothing), then `POST /api/project/move` with the picked folder and this window's session client id, then the page reloads at the new project path. Move waits, with a plain message, while edits are still queued to save (checked before the dialog opens and again after a folder is picked) and says so when the computer has no folder dialog; each row shows the server's refusal under the section; the episode stays where it is until a move succeeds; if the folder moved but a later step failed, the page reloads at the folder's new path), **Models** (closes Settings and opens the Models sheet) and **Keyboard shortcuts** (inside a project only: closes Settings and opens the command palette). The palette's **Report a problem…** opens the same sheet straight on the report step (a sheet, since the palette was not beside the button), and **Guides** (`help.guides`) opens the documentation site in a new tab) and shows the Import and Record key caps on the tiles (`stages/home/useHomeKeys.ts`; Mod+N and Mod+R stay the browser's). A card opens a menu on right-click, long-press or the Menu key: **Open**, **Reveal in folder**, **Duplicate** and **Remove from list** (a card whose folder moved offers only Remove from list); on the phone a row also swipes left to show **Remove from list**. Remove from list calls `DELETE /api/projects/recent` and never touches the episode. **Import audio** (or dropping audio anywhere on Home) creates an episode named after the first file in the default folder (`~/ShareCut/<name>`, `PODCAST_WORKSPACE_ROOT`), uploads the files and opens Prepare, which starts processing at once; **Record** creates an "Untitled episode" and opens Record. The Setup card appears when the audio tools or a required model are unavailable (`/api/bootstrap/*`). In the **Models** sheet, the Transcription row has a Fast / Balanced / Best segmented control (`WhisperSize`), with size labels from the current variant catalog. Choosing a size refetches its status without starting a download. `/api/bootstrap/status` reports every registry model in `models`, each with a `tier`, `state` and `size`. While a download runs its row shows a real byte bar (`download.bytes` of `download.total`, indeterminate when the total is unknown) and the other rows are queued; a failed row shows the typed failure and **Try again**. Studio reads that status through one `ModelsProvider` (`gui/web/src/models/`, mounted by `App` for the host, not on review, record or `share:` guest routes): it fetches status and the current `status-job` once at mount, adopts a download it finds running (a reload or a second tab shows the bar), fetches status again when a job ends or a Whisper size is chosen (never on a progress frame), and never starts a download except from `download()`. `waitForBootstrapJob` resolves with the terminal snapshot (`ok`, `error` or `cancelled`, `failure` and `result` intact) and rejects only when the connection is lost or the wait is aborted; a failed model is per-row data read from `result.results[id]`, kept in memory for the session. **Models** is the other place to see and fetch them: the **Models** row of the **Settings** sheet (from the app menu's **Settings** row on Home and in a project; the row is always there, also when the Setup card was dismissed), and the palette command `models.open` (**Manage models…**, host only) in a project. Both open `ModelsSheet`, whose Model need rows act as they change: **Get**, **Update** (sent with `force`), **Try again** after a failure, and a progress ring that cancels while it runs. The server has one download slot, so while one runs every other **Get** is disabled with "Another download is running"; a download another tab started is adopted and shows its progress. Opening and closing the sheet never starts a download. An adopted download of another Whisper size keeps the selected size unchanged. A separate job row names the active size and offers its byte progress and Cancel; its failure and Try again stay attached to that size. Home summarizes that active download too. An installed or out-of-date model has a more menu with **Remove** (after a confirm: "This frees about 1.6 GB. Get downloads it again."), which calls `DELETE /api/bootstrap/models/{id}` (`?whisper_model=` names the one Whisper size); the server deletes only what Studio downloaded (a path set by `PODCAST_MCP_RNNOISE_MODEL` or `PODCAST_MCP_SPEAKER_ECAPA_MODEL` is refused with 409 `model_not_removable`), refuses with 409 `bootstrap_job_running` or `pipeline_busy` while a download or job runs, answers 200 with `{ok, freed_bytes, model}` (logical regular-file payload bytes, excluding snapshot links, and the model's record after), and an uninstalled model frees 0 bytes. `GET /api/project` (and create/open) pins `served_project` for host MCP; only Studio **New project** (`project.new`) calls `POST /api/project/close` to unpin (then opens `/?home=1`; if the unpin fails or has not answered within 10 s, Studio stays open and reports it in the status line; after a timeout it also re-pins the open project (best effort: the server may still finish the stalled unpin late, leaving host MCP unpinned until the next project load); a repeat New while it waits is ignored; New and Open are refused while this tab is recording, in a browser as well as the desktop app, and if a leave-page prompt keeps the page after New, New works again after 5 s); creating or opening a project re-pins. Home itself never unpins. While a project is pinned, a bare `/` (no `project`, `review` or `home` param) 307-redirects a host-authorized browser to `?project=<served>` (a query-only relative `Location`, so a mount prefix or path-rewriting proxy keeps its path; other params such as `sc_close_guard` kept), so a bookmark, tab restore or preview tool can't unpin it; `/?home=1` shows home without unpinning. Non-loopback still requires `--project` (pinned; switching projects is loopback-only) and does **not** mount `/mcp`.

Navigating the browser to `/?project=<other>` while a project is pinned returns the app itself with HTTP 403: the server embeds the served episode's name and the two links in a JSON element (`#sharecut-not-served`) and the app draws the Status cover (`gui/web/src/stage/frame/StatusCovers.tsx`), "This episode isn't open on this computer", with **Open <name>** and **All projects** (`/?home=1`, home without unpinning). The page is returned only for requests that accept `text/html`; API clients receive the JSON `403 {"detail":"project path not allowed for this server instance"}`. On a non-loopback strict-auth server, the request must carry the launch `session_token` before the page reveals served-project metadata, and both links retain that token. The page is an owner surface gated by the host role (`require_host`), so relay-tunneled requests (`x-sharecut-relayed`) get the JSON `403` and never see the served project's path, even from loopback or in non-strict mode. While a project loads, the **Loading cover** (`gui/web/src/stage/frame/StageLoading.tsx`) draws nothing for 300 ms, then the real Stage bar with the project name taken from the path and static grey blocks in the layout of the stage the project opens on (Home's card stage, else Prepare; Review for a review link), and after 4 s "Still loading…" with **Retry** (a reload). It shows no spinner and no "Loading" text.

The loopback GUI is a **privileged local RPC** (not “safe because localhost”). Host/Origin binding rejects DNS-rebind forged `Host` headers on host APIs. Treat `127.0.0.1:8765` like a local agent with full project open/create and pipeline powers. Owner GUI routes also require the **host role** (`gui/routes/deps.require_host`): a loopback peer, or `PODCAST_SESSION_TOKEN` under strict authz — never relay-tunneled traffic, even from loopback. On a host whose `HostPlatform.loopback_is_trusted` is false (iOS: other apps on the device can reach loopback) every owner route requires the owner session cookie, in or out of strict mode, and nothing else is accepted (not the loopback peer, not `PODCAST_SESSION_TOKEN`, not `X-Podcast-Token` or a `token` query); the host MCP mount `/mcp`, the handoff routes and the API docs are not served. See [host-online-relay.md § Security notes](host-online-relay.md#security-notes).

`GET /api/tunnel/status` (host role; feature `tunnel.status`) reads cached tunnel snapshots and returns one selected status. The response includes `state` (`online`, `connecting`, `reconnecting`, `offline`, `off`, `not_set_up`), `phase`, `reason`, `reason_kind`, `relay_host`, `public_base_url`, `share_count` and `retry_at` (the next reconnect time in epoch seconds, or `null`). The shared flow polls it every 5 s while Deliver or the Invite sheet is open, when `share.ui.menu` and `tunnel.status` are available. When there is a tunnel status message to show, it appears in the Invite sheet. Listen rows with a URL show the link's network scope in both Invite and Deliver. The response carries no token. See [host-online-relay.md § Tunnel status](host-online-relay.md#tunnel-status) for state messages and retry display.

**Native shell (optional):** Tauri 2 under [`gui/desktop/`](../gui/desktop/) spawns `podcast gui` and opens a WebView on the same URL. Packaging boundaries: [desktop-packaging.md](desktop-packaging.md).

**From an agent (MCP):** `open_gui_tool(project_path=…)` starts the viewer in the background (or reuses a healthy server on `:8765`), opens the browser, and returns the URL. CLI equivalent: `podcast gui --project … --background`. Skill: `podcast-open-gui`.

### Embedded entry

A host process that cannot start `podcast gui` as a subprocess (the iOS app's embedded interpreter) serves Studio with `podcast_mcp.gui.embedded`: `start()` builds the app once (`create_app(host_mcp=False)`: the host MCP session manager runs once per process and an embedded host never serves MCP), binds `127.0.0.1:0` once with `exclusive_listen_socket`, holds that socket until the engine ends, runs uvicorn (access log off) on a daemon thread and returns `Started(port, exchange_code)`; a second call returns the same port with a fresh code. `exchange_code` is None on a host whose loopback is trusted. On a host whose loopback is not trusted it is a single-use code the web view's first navigation trades at `/api/session/exchange?code=...` for the owner session cookie ([host-online-relay.md § Security notes](host-online-relay.md#security-notes)). The engine starts once per process, because serving the same app a second time reruns its lifespan, which stops job leases and file watchers. `stop()` ends the server thread (an open event stream is cut after `timeout_graceful_shutdown`, 2 s), closes the held socket and is safe to repeat; a later `start()` raises `EmbeddedStartError` ("the engine was stopped; reopen the app"). A server thread that dies on its own ends the engine the same way. A start that fails before the app serves keeps the held socket, so a retry gets the same port. The state is `Idle` (nothing has served), `Serving(port)`, `Failed(reason)` (never served; retry allowed) or `Stopped(reason)` (served and ended; terminal). A failed start keeps a one-line reason in `status()`, raises `EmbeddedStartError` with it, and writes the traceback to `engine.log` in the host's first log directory. `bind.build_gui_server` is the one uvicorn wiring `podcast gui` and the embedded entry share. There is no CLI command or MCP tool for it. The native shell that performs the first navigation is a later part.

## Local host MCP

While `podcast gui` is running, the DAW is a spec-compliant MCP server (Streamable HTTP, official Python SDK). Open an episode, then **Menu → Connect agent…** and paste:

```json
{
  "mcpServers": {
    "sharecut": {
      "url": "http://127.0.0.1:8765/mcp"
    }
  }
}
```

Keep ShareCut Studio running. Host `tools/call` applies to the **pinned** episode (`served_project`); with no pin they return an error to open one first. The host transport is stateless: requests do not retain MCP sessions and the server does not issue or require a sticky `Mcp-Session-Id` header. The host endpoint accepts POST; GET and HEAD return `405 Allow: POST` because a standalone SSE stream cannot receive events from another stateless request. A legacy cancellation notification sent in a separate POST cannot stop an in-flight call; [issue #151](https://github.com/calebn/sharecut-studio/issues/151) tracks that compatibility gap. `/mcp` is mounted only on loopback binds. This is not OAuth and not a share token — loopback + Origin/Host DNS-rebinding checks only. Guest/collaborator agents still use `{base}/mcp/{token}/mcp` ([host-online-relay.md](host-online-relay.md) § Remote MCP), and contributor stdio `podcast-mcp` keeps its session behavior.

Model removal and host tool execution share process-local admission. A host call excludes removal until its body exits, even before a progress chip appears or after its chip is replaced by newer activity. A call arriving during removal returns a retryable `job_running` refusal before its handler runs. Status and cancellation remain available. Separate processes and external cache writers are outside this guard.

Dev mode (API `:8765`, Vite `:5173` with `/api` proxy):

```bash
podcast gui --project /path/to/episode.sharecut --dev --no-open
cd gui/web && npm run dev
# open http://127.0.0.1:5173/?project=/absolute/path/to/episode.sharecut
# or omit ?project= for host New/Open home (loopback API)
```

## Project / track / audio ingest (Pass 8)

Host and share **`edit`** guests may add tracks, attach/replace audio, edit track meta, and remove tracks. **New / Open project** is host-only.

| Path | Role |
|------|------|
| `POST /api/project/create` · `POST /api/project/open` · `POST /api/project/close` | Host loopback — create empty episode (a blank `workspace_dir` means `<PODCAST_WORKSPACE_ROOT or ~/ShareCut>/<name>`, numbered " 2", " 3" when taken; a name Windows reserves for a device, such as `con`, `nul.wav` or `com1`, is refused with 400 `project_name_reserved` and never renamed, on every OS so a folder moves between machines; Home's drop names an episode after the day when its file is called that), open existing `episode.sharecut` (a workspace **directory** or the project's retired entry file is also accepted and adopted, see `project-format.md`), or unpin `served_project` (Studio New project). CLI `--project`, MCP, and `open_project` still load any JSON path. A folder name that is not valid UTF-8 is refused **400** `project_path_invalid` before anything is pinned or recorded. |
| `GET /api/projects/recent` · `DELETE /api/projects/recent?path=` · `POST /api/projects/recent/reveal` · `POST /api/projects/recent/duplicate` | Host loopback (same guards as the project-switching routes; other peers get **403** `project_recent_not_allowed`, relayed requests **403** `authz_denied`) — Home's list: the last 20 episodes opened or created on this machine, newest first, as cards `{path, name, opened_at, edited_at, duration_sec, stage, chip: {text, state}, peaks, folder_missing}`. Shares the single-dialog lock with `pick`: an overlapping call is **409** `file_dialog_open`. Touches no project. |

## Transcript speaker editing

Speaker labels in the transcript open a name editor for hosts and shares with the `edit` capability. Enter a new name or choose an existing speaker, then select **Save speaker** or press Enter. The change applies to every turn on that track through the same `SetTrackMeta` command as the Track inspector. It preserves source audio, word timing, and track identity. **Cancel** or Escape discards the draft. History Undo restores the previous speaker. The adjacent timecode seeks the turn. Queued saves immediately update the visible speaker labels and announce that delivery is pending. Rejected saves restore the previous view only if the originating project and optimistic snapshot are still active.

## Transcript refine recovery

Two host-only routes sit beside the waiver: `POST /api/transcript/refine/done` (`{path, notes?, expected_fingerprint?}`) marks the transcript checked and `GET /api/transcript/refine/status?path=` reads the gate. See [gui-integration.md](gui-integration.md#transcript-check-routes). The web client has `markTranscriptChecked` and `loadTranscriptCheck` (`api/transcriptCheck.ts`); no control calls them yet.

The host-only `POST /api/transcript/refine/waive` endpoint accepts `{path,
reason}` and records the waiver through `TranscriptRefineService` with source
`user`. The GUI exposes it only when an approval receives the transcript-refine
gate error. A replayed (queued) approval refused by the gate shows the same
**Cut anyway** button in its **Needs attention**
row in the Review queue. There is no text box: Cut anyway saves the canned reason "Cut anyway, chosen by the host". Share guests cannot use this recovery path; waiving never approves
the pending edit automatically.
The document-command gate responds with HTTP 409 and
`X-Sharecut-Error-Code: transcript_refine_required`; the GUI uses that stable
code to show recovery guidance without exposing the CLI-oriented server hint.
The waiver route is host-origin protected and serializes its project save with
document commands.

An Approve click made while another live host command from the same tab (or this tab's offline-queue drain) is still in flight waits for it (up to 5 s in total, `DOCUMENT_SEND_WAIT_MS`) and then posts, so the typed 409 reaches the inspector. If the earlier work is still running after 5 s, the approval stays queued for the drain: the Pending edit inspector, and the Review Queue show a **Still sending** status instead of treating it as done (it clears once the project's command queue is empty), and a refusal of the later replay appears in the **Needs attention** group of the Review queue, where a transcript-refine refusal offers the host **Cut anyway**.

## Busy project (503)

Any HTTP route that does not map `project_commit_lock` / `render_lock` contention itself falls through to an app-wide FastAPI exception handler (`gui/routes/deps.py::project_busy_exception_handler`, installed on `Timeout` in `create_app()`), which returns HTTP 503 with `X-Sharecut-Error-Code: project_busy` and a fixed, path-free message (`util.project_state.busy_message`). `document.py`'s own `Timeout` / sqlite-busy mapping (same `busy_message` text for a lock timeout, so a render-busy command keeps its render advice) and the `/api/audio` render-busy path keep their existing, more specific contracts; the app-wide handler only covers routes (such as `/api/comments`) that would otherwise surface a raw 500 (#488). Routes that catch broad errors themselves map a lock timeout the same way before their generic fallback: guest review, recording, waveform, and upload routes (`gui/routes/guest_errors.py` over the shared `tool_refusal` policy, including chained SQLite busy errors), owner waveform routes (`waveform_call`, which does not log it as a fault), and owner media-upload routes. `PUT /api/transcript/vocabulary` maps a transcript-context lock timeout to the same 503 `project_busy` code, keeping its own `TRANSCRIPT_CONTEXT_BUSY_MESSAGE` text. The app-wide HTTP handler does not handle WebSockets. Guest review and recording adapters explicitly classify contention as `project_busy`: admission or setup closes with transient `1013`, while recording commands send `invalid_state` with `error_code=project_busy` and leave the socket usable. Owner WebSocket handling is unchanged. Edits reach the project through the HTTP command routes (`POST /api/document/command`, guest `POST /api/review/{token}/daw/document/command`), which are covered. See [architecture.md § Staleness](architecture.md#staleness) and [persistence.md](persistence.md) for the underlying locks.

## CLI commands while Studio is open (#1733)

Studio and the CLI both write the project file, so a CLI command used to fail with `Project is busy in another process` whenever Studio held the project lock (building the mix, saving). While a Studio is serving a project, the CLI therefore hands each project command to that Studio instead: Studio is the only writer, the change shows on screen as it happens, and nothing is stopped or restarted for the CLI. With no Studio serving the project, the command writes the file directly, exactly as before.

Discovery reads the announcement from the requested resolved project path's parent folder before comparing existing files by filesystem identity. A same-folder hardlink can find Studio's announcement, but a hardlink in another folder does not discover it. A missing or inaccessible project file does not match, even when both paths have the same spelling.

CLI command execution requires Studio's served filename. A distinct hardlink name is refused with `project_alias` before the command runs or falls back locally, including read commands. Use the served filename or its workspace folder. Symlinks that resolve to the served filename still work. This prevents an atomic save through an alias from updating only that alias while Studio keeps the old file. It does not protect direct commands with no discovered Studio, an explicit handoff opt-out, or an alias already separated by an earlier atomic save. MCP forwarding still uses the served filename.

This protection requires an updated Studio. An older CLI stops on the new refusal without replay, but reports that the command may have run. An updated CLI against an older Studio retains the older server behavior.

- **Discovery.** A Studio that serves a project writes `artifacts/studio-host.json` (mode 0600: run id, pid, address, port and a per-run token) once it accepts connections, rewrites it when it switches project (`gui/routes/handoff.py::set_served_project`) and removes it on exit. The file can outlive a crash, so it is only a pointer. The CLI asks the address in it (`GET /api/handoff/ping`). The address is `127.0.0.1` (or `::1`) for a loopback or wildcard bind. A Studio bound to `127.0.0.2` or a LAN address announces that address and this machine's name instead (`StudioHostState.address`, from the socket's own address), and no client may ping it (Studio's peer and Host checks reject it), so the CLI only checks that something listens there with a bare connection (no bytes, no token) and, if so, refuses the command, reads included, with a message naming the Studio, the address, the two ways out (restart with `--host 127.0.0.1`, or `PODCAST_NO_STUDIO_HANDOFF=1`) and the announcement file; a refused connection means the file is stale, a timeout or any other failure also stops the command with the same announcement-file hint, and a file written on another machine (a different first name label, compared without case) is ignored. A refused connection, a different run, or a supported reply that says the run serves another project means no Studio serves this project, so the CLI writes directly. A non-200 response, an invalid or incomplete reply, or an unsupported protocol from the matching run stops the command instead of writing locally. A connection reset while reading the ping body is an incomplete reply, even after successful response headers.
- **Which commands.** Any command that names `--project`, except the groups that act on the caller's machine (`gui`, `play`, `record`, `tunnel`, `fixture`, `config`, `setup`, `doctor`, `bootstrap`, `session`; `cli/handoff.py::NOT_HANDED_OFF`). Relative paths in the arguments are made absolute first, because Studio's working directory is not the caller's. `--help`, a path read from stdin (`-`) and an option the reader does not know run directly.
- **What runs.** Studio runs the unmodified `podcast` command in a worker thread (`POST /api/handoff/run`), so every flag, refusal, exit code and edit-log attribution (including `--override-audio-checks`) is the same as a direct run. The command's stdout and stderr are routed back to the caller as newline-delimited JSON (`util/stream_routing.py`); no progress is drawn for a human at a terminal (the output is not a terminal, so the reporter is silent, as in `docs/cli-progress.md`); `--json-progress` events are relayed. The first Ctrl+C in the caller requests cooperative cancellation in Studio (`POST /api/handoff/cancel`). The cancel request and its acknowledgment share one five-second deadline, including trickling response headers or body bytes. A failed cancel request is best-effort; the caller then waits up to 30 seconds of stream silence for the command to finish. A second Ctrl+C stops waiting immediately. The caller closing the connection also requests cancellation.
- **Waiting.** If Studio is busy with its own job for the project (the mix build, an export), the command waits for it and the caller's stderr says what Studio is doing and for how long; it starts when the job ends instead of failing with a busy lock. Cancelling while it waits stops it before it starts.
- **Safety.** The routes need the announced token on top of the loopback and Host checks every host route has, and never accept relayed traffic. Studio refuses a command that would not hand off (a different project, an unknown shape) and every `PODCAST_*` setting the caller has must match Studio's (names containing TOKEN, KEY, SECRET, PASSWORD or SIDECAR are not compared or sent, and a setting only Studio has is not detected), otherwise the CLI says which setting differs and writes directly. At most eight handed-off commands run at once. The CLI asks Studio whether it serves the project (a 5 s ping, tried twice). A Studio that accepts the connection but stays silent, or answers the ping with a 200 whose body is empty, not JSON or not an object, is never bypassed: the command stops with an error and writes nothing. A run request Studio does not answer in time also stops the command with an error that says it may already have changed the project; the command is not repeated. A socket timeout (including Windows error 10060) stops the command the same way a silent Studio does; a refused connection does not. A retry that fails after a timed-out first ping stops the command too, whatever the failure. An announcement nothing listens for is stale, and the command writes directly. `PODCAST_NO_STUDIO_HANDOFF=1` opts a command out.
- **When it breaks.** A defined pre-execution refusal from Studio preserves its direct-write behavior; other defined authorization or capacity refusals print Studio's reason. If the command's POST loses its reply, returns an unexpected HTTP refusal response, or loses its output stream, the CLI warns that the command may have run and changed the project, then stops without writing locally. After Studio confirms the command started, the warning says so. Check the project before retrying. A Studio that disappears after a successful ping but before the command reply also stops the CLI conservatively.

**Stdio MCP (#1753).** The stdio `podcast-mcp` server does the same for tool calls (`mcp/studio_handoff.py`, installed only by its `main()`, so Studio's own copy of the tools never forwards to itself). For a tool that takes `project_path` (explicit, or the `PODCAST_MCP_PROJECT` default), the server asks `locate_studio`; if a Studio serves that project and mounts `/mcp`, it calls the same tool on Studio's loopback endpoint (which binds the served project) and returns Studio's result unchanged. Completed tool results survive late heartbeat replies during shutdown. The session owns separate stream handles, so closing it leaves the transport's handles open until its pending tasks stop. If no Studio serves the project, the call runs in the calling (stdio) process as before. A Studio that does not mount `/mcp` (it is bound to a non-loopback address, though a wildcard bind still announces itself on `127.0.0.1`) is not bypassed either: the tool returns an error naming the Studio, saying nothing ran, and offering a restart with `--host 127.0.0.1` or `PODCAST_NO_STUDIO_HANDOFF=1`. The same holds for a Studio bound to `127.0.0.2` or a LAN address, which cannot be pinged at all: the tool returns the error the CLI prints for it (see Discovery above), and nothing runs. A Studio that answers with a non-200 response, an invalid reply, or an unsupported protocol from the matching run is not bypassed: the tool returns an error and nothing runs. A Studio that accepts the ping connection but stays silent is also not bypassed. If the ping finds a Studio serving the project but Studio cannot be reached before the call is sent (for example the connection is refused or the MCP initialize fails), the tool returns an error saying Studio did not take the call and nothing ran. If Studio stops answering after the call was sent, the tool returns an error saying the call may already have changed the project and is not repeated. When the agent's request carries a `progressToken`, Studio's `notifications/progress` for the call are forwarded to it as they arrive, so a long mix or render reports progress as it does in the stdio process; without a token nothing is sent, and a client that stops listening never fails the call. `PODCAST_NO_STUDIO_HANDOFF=1` opts out. A forwarded call may run as long as it needs while Studio's event loop answers MCP pings; a Studio that answers none for about 75 seconds after it took the call ends it with the same "may have changed the project" error (a tool wedged on a thread of a Studio that still answers is not detected). An agent connected to Studio's own `/mcp` URL already goes through Studio.

## Host file not private (500)

A share registry file or folder that is not private to the host user raises `RegistryPrivacyError` (`util/registry_privacy_error.py`, code `registry_not_private`) from any route that opens the registry; a review artifacts or staging folder that is not private raises `ReviewPrivacyError` (`util/review_privacy_error.py`, code `review_artifacts_not_private`). Both are `HostSetupError`s (`util/coded_error.py`). An app-wide handler (`gui/routes/deps.py::host_setup_exception_handler`, installed in `create_app()` next to the busy handler) returns HTTP 500 with `X-Sharecut-Error-Code` set to that code. The host reads the message with the path and the fix; any other caller reads the error's fixed guest message, through the same `tool_refusal` policy as every guest surface. Guest review, recording and MCP routes, and the share-identity middleware, answer through `guest_http_error`, so they return the same coded 500 JSON instead of a bare server error. See [share-tokens.md](share-tokens.md).

## Keyboard clip handles

Focused timeline fade and trim handles accept Left/Right arrows through the shared command bus. Fade steps are 1 ms (Shift 10 ms); trim steps are 10 ms (Shift 100 ms), without snapping. Right grows fade-in, Left grows fade-out; Right advances either source boundary. Holding a key previews repeated steps and releasing that arrow saves once, so one Undo restores the gesture. Normal blur also saves; Escape, pointer cancellation, unmount, or changed project/clip geometry discards the preview. An in-flight save blocks another handle gesture. Fades preserve the opposite edge and clamp to the clip length the opposite fade leaves (a fade you set has no join fade limit); trims preserve minimum span and neighbor bounds. A handle that retains native focus after a project reload edits the fresh clip. Removing the focused handle releases keyboard ownership. Arrow keys outside a focused handle retain playhead navigation.

The selected clip Inspector lists Start, End, Length, Source start, Source end, Fade in, Fade out, Fade in shape, Fade out shape, Gain and Track. End and Length are Scrub fields in timeline seconds that trim the out edge (read-only on a clip with timing steps), and Source start and Source end are Scrub fields for precise trim targets. Arrow keys and drags stop at the current source, minimum-span and neighboring-clip bounds; a typed value outside them is refused with the range named on Enter and dropped on blur. A committed value (Enter, blur, an arrow key or a drag end) is submitted once through the existing trim command. Arrow keys step 10 ms (Shift 100 ms, Alt 1 ms). Pending-edit source boundaries use the same two nudge sizes, and, in the phone's compact drawer, a selected envelope point exposes 10 ms and 100 ms time nudges plus ±0.5 dB level nudges. These buttons keep the 44 px Inspector target size and use the same existing document mutations as their drag or typed-edit paths, so each accepted action is one Undo entry. Envelope levels remain linear multipliers in the project. A +0.5 dB step from exactly 0× starts at the existing −60 dB floor and yields −59.5 dB; a downward step remains at zero, while positive values below the floor retain their multiplicative step.

A held trim in the inspector has one detachable display layer in the
project store. Its run token and captured path, epoch, document generation,
sequence and authoritative project establish ownership. Every accepted step
computes `trimDraft` from the clean origin and publishes the layer, preview and
zoom clamp together. A refused step leaves the last accepted value unchanged.

Transformation writers use `projectEditBasis()` before constructing a result
or rollback baseline. The basis excludes the held trim and retains current
pending drafts and local results received before the hold. Ordinary
`setProject()` publications and hydration retire the layer atomically. Returned
comments, action updates, moves, track metadata, reorder, mix and queued
envelopes therefore cancel the trim while keeping their own changes. An
unchanged pending mix publishes nothing and permits the hold to continue.
A splice's synthetic tails disappear and deleted original rows return when
only the trim layer is discarded. Clip commands reject targets absent from
the clean basis before submission; Copy and Cut also read that basis.

A same-lifetime discard reapplies current pending drafts over the origin.
A lifetime mismatch can use only ready authority for the current path, with
its pending drafts. Otherwise the clean reader returns null until replacement
or hydration; it never supplies the contaminated old display as clean data.
Releasing or unmounting a stale run saves nothing. Its pointer release click
remains consumed even after a delay. A current release or normal selection
unmount freezes the exact accepted preview and saves once. The layer remains
in its saving phase through boundary loading and command settlement. Both phases
provide a clean editing basis. Publication retires either phase atomically.
After boundary loading, submission requires the same saving token and document
lifetime. Settlement removes only the matching saving layer, retaining current
pending drafts. Undo waits through that cleanup.

Fade gestures capture both saved fades and both saved curves and submit the lengths with `SetClipFade`; the curves ride in its `expected` baseline (a missing curve is `linear`), so a length edit on a curved clip is not refused.
The server refuses a stale pair before history capture, including a draft made
while an Undo reply was delayed. The current project shows "This clip changed.
Nothing was saved. Adjust the fade again." Timeline handles
and the Clip Inspector fades announce it visibly (the status line says "Fade in not saved: ..."); a refused trim, join or Ripple delete shows in the sheet as an alert. A fresh gesture uses the
restored pair. On a coded `clip_fade_changed` refusal, the shared command queue
refreshes the current project through `refreshDocumentProject` before reporting
the refusal, even when a peer's WebSocket projection is delayed. This also applies
to host and guest offline replay. The rejected command keeps its original
baseline and identity, leaves the queue permanently, and remains in **Needs
attention**. A failed refresh preserves the original refusal. A delayed refresh
cannot apply to a switched project or a reopened project generation.

## Pointer draft ownership

A clip body keeps its existing pointer selection and focus policy. Its key
handler exists only for the admitted pointer gesture: Escape cancels it;
arrow, endpoint and activation keys stay local until release. Every terminal
path removes the handler. This is the component Escape exception to keyboard
listener governance and dispatches no global command. Timeline admission permits
one body owner, and move/range cancellation checks its own draft before clearing
shared preview state. Chapter and social marker keys remain on their focused
buttons. Project path and epoch key their marker lifetime, so an identical
marker in another project cannot inherit a held gesture. Cancellation compares
the actual serialized painted geometry. These previews create no document
History.

The panel separator reports measured height to assistive technology even when
CSS chooses the responsive default and its preference remains unset. Its title
exposes arrows, Shift for larger steps, Escape cancellation and Enter reset.
The measured pointer strip remains 10 px high; keyboard resizing is the available
alternative, and physical touch comfort remains a manual validation gap.

## Clip join fields

`list_clips` / the project view give every clip row the effective render of its incoming join as flat fields: `join_left_clip_id` (null for a track's first clip), `join_render_mode`, `join_crossfade_ms` and `join_crossfade_blocked` (`not_abutting` | `no_fade_out` | `no_fade_in` | `no_headroom`, the last when the recordings have no room past the seam to borrow from). ## Project save state

A host project shows one save state, so "did that save?" never needs the History tab. It is derived, not tracked: `stage/frame/saveState.ts` (`saveStateOf`) reads three facts the editor already holds, and `SaveIndicator` renders the result in the header. The text lives in the dot's accessible name and `title`, and in the **Needs attention** group.

| State | Read from | Light (shape, colour token) | Name and `title` |
| --- | --- | --- | --- |
| Saving | this tab has an edit save preparing, a live send in flight or a queue drain running (`documentActivityBusy` in `state/documentSendOrder.ts`) | ring, `--color-text-secondary`; pulses, static under `prefers-reduced-motion` | `Saving to project…` |
| Waiting to send | edits in the host offline queue (`host-queue:{projectPath}`) with nothing in flight | hollow circle, `--color-warning` | `Not saved yet · N waiting to send` |
| Save failed | a queue that cannot be read (a refused command is listed in Needs attention but is never a failed save: nothing was written and nothing lost) | rounded square, `--color-danger` | `Save failed` |
| Saved | none of the above, after the queue has been read once | solid circle, `--color-success` | `Saved to project` |

Colour is never the only cue (WCAG 1.4.1): shape carries the state alone, so red and green stay apart under deuteranopia. Every colour is a semantic theme token and holds at least 3:1 against the surface in both themes (measured: light 4.7 success, 4.9 warning, 6.1 danger; dark 8.6, 9.2, 6.3; the neutral ring is 7.7 in dark and uses the secondary text token). Only a failed light is a button, and its Retry depends on the cause: a refusal or unknown outcome opens Review at **Needs attention**; an unreadable queue is passive for a host (the group's own **Retry** row is the control) and re-reads the saved queue for a share guest; saving, waiting and saved are read-only status images. The painted dot is `--save-dot-size` (0.5 rem) and its box `--save-dot-box` (1.25 rem). A read-only light takes no tap and paints no target. The light sits in the app header on every shell, so a Waiting or Failed light never adds a row or moves stage content, and no banner row exists above the body. Playwright pins that a failed header does not scroll and that its Retry and the Review queue's Retry are full 44 px touch targets (`gui-surfaces.spec.ts`). On a phone a failed light keeps Retry in the header and the stage reachable, and in a short window at twice the text size (an app container at most 24 rem tall, such as landscape) Review keeps a positive-height body, the frame never scrolls, and the queue sheet's Needs attention group keeps its Retry reachable (`phone-save-attention.spec.ts`).

Saving wins over the others because an edit on its way is the freshest fact. It also holds from the moment a send ends until the first queue read after it resolves (`settling` in `AttentionSnapshot`), so a send that ended on a dropped socket or a refusal never shows Saved from the stale snapshot. The dot is not drawn until the queue has been read once, so it never claims Saved before it knows. The queue and conflict read is the one shared poll in `services/offlineQueue/offlineAttention.ts` (2 s, plus an immediate read when a save or drain ends) that the **Needs attention** rows also use. On a host project the rows (`review/ReviewQueue.tsx`, fed by `stage/hosts/useReviewAttention.ts`) are the text cue beside the colour and hold the actions: **Send now** beside the waiting count (`requestHostDrain`) and **Retry** when saved edits cannot be read, each a shared `Button`. A "See why" press on the dot opens Review (`stage.review`) and moves focus to the group. Every `failed` state has a row by construction: it is the unreadable line, and a refusal is a listed conflict that never turns the light red. The dot makes no announcement of its own. Queue and conflict count changes speak once through the shell status region (`useOfflineAttentionAnnouncement`, run by `OfflineAttentionAnnouncer` for host and guest projects alike), on every stage. The group is a `role="group"`, not assertive `role="alert"`, so ordinary attention updates do not duplicate assertive announcements. Share guests get the same header dot from their own offline queue (`share:` key): Saved, "N waiting", Save failed with Retry (re-reads the queue), and "Saved copy · N waiting" with a hollow cloud when the host cannot be reached and the cached copy is open read-only.

A command that cannot write the project (disk full, a read-only or not-writable folder, an I/O error) is answered by `POST /api/document/command` as a 5xx with code `project_write_failed` and plain words that name the cause and the fix, never the file path (`project_write_failed` in `util/write_failure.py`; a policy `CodedPermissionError` stays a 403 refusal). The client records it as an unknown outcome with that text instead of "The server may have applied this edit", and Send now retries it. Undo and Redo handle the same answers: a missing or damaged project file is the same red "Not saved" refusal, and a write failure keeps the server's words followed by "Check History before trying again", because an Undo must not be replayed blindly. The classification lives in `util/write_failure.py` and is applied once, in `DocumentSyncService.submit`, so the guest route (guest copy: "Your change could not be saved on the host's computer. Ask the host to check that its disk has space and is not read-only"), host MCP and the CLI raise the same coded `ProjectWriteFailedError` instead of a raw traceback.

A project file that is missing (404 `project_not_found`) or damaged (`load_project` raises `ProjectUnreadableError`, answered 500 `project_unreadable` by `project_unreadable_exception_handler`) is the one refusal that turns the light red: nothing can be saved until the file is back. The client records a refused outcome with `blocksSave: true` and plain words (`projectUnavailableReason` in `utils/apiError.ts`), the light shows "Not saved · …" and opens Needs attention, there is no Retry because retrying cannot help, and the outcome clears when it is dismissed or a later command saves.

It sits in the app header on every shell, next to Undo and Redo (`System/SaveIndicator`, `stage/frame/useSaveIndicator.ts`). It is a small dot with no visible text, except for a guest on a saved copy, where it shows the words "Saved copy · N waiting" (a cloud and the count on a phone). It is read-only when saved or saving (`pointer-events: none`), so it never covers a control. Waiting and failed are tappable, so the target is `--touch-min` tall. A live recording or Solo chip is a Stage bar badge and a Player bar chip and does not move the dot. The Vitest placement tests are in `stage/frame/StageFrame.test.tsx` and `stage/frame/saveState.test.ts`.

The frame is a grid with named areas `header / banners / alerts / body inspector / player / tabs` (the tab bar row exists on a phone only). Banner rows are always `auto` (0 when empty), so a banner never shifts another child; stages change only what the body holds. Guarded by `gui/web/src/stage/frame/StageFrame.test.tsx`. Stages are switched by the Stage bar, `Mod+1`–`5` and the palette; the palette (`stage/dialogs/CommandPalette.tsx`) lists **Recent** when its search is empty (kept per browser in `localStorage`), the commands by category (each with its verb icon when the verb table has one), then **Stages** (before Projects, People and Chapters; the five Go to <stage> commands, with the same `stageAllowed` gates and reasons as before, so a review or guest link sees the stages it cannot enter disabled), **Projects** (host only; `project.open` with a path), **People** (`presence.follow`), **Chapters** (`transport.seek`), **Gestures** (a touch pointer inside a project only, never on Home: one row per `MOBILE_GESTURES` entry, the action with its gesture name; Enter and click do nothing) and **Help** (Gestures and Help come after Chapters) (`help.*` commands: Report a problem…, shown disabled with its reason on a guest or review link) groups that are hidden while empty; a search lists commands flat (Stages and Help rows labelled by group) and keeps the entry groups and Gestures after them; Script is toggled by `T` and focused by `Shift+T` (see `docs/gui-mobile.md` § Desktop — Script and Timeline).

## Live project reload

The viewer sanity-polls `GET /api/project/meta` every 30 s and when the tab regains focus (`SANITY_POLL_MS` in `gui/web/src/state/syncCadence.ts`; includes document `server_seq`; #662). Other processes' journal writes normally arrive sooner, over the socket, via the server's cross-process watcher (`services/document/cross_process_sync.py`, #695); this poll is the sanity net. `project_meta` is stat + `document.db` read, no project parse, never creates `document.db`. When `mtime_ns`, `size` or `server_seq` change (a `server_seq` change counts only between two readings; a response without `server_seq` is skipped) to a file this client has not already applied (from the document socket or its own command result) and local seq is behind, it re-fetches `GET /api/document/state?phase=shell` and merges into the timeline **without a browser refresh**. Playhead, zoom, and selection are preserved. JSON responses are gzip-compressed (`GZipMiddleware`); document WebSocket uses permessage-deflate (`ws_per_message_deflate=True` on uvicorn). Do not gzip audio `FileResponse`.

Host tabs subscribe once to `WS /api/host/ws` for session, document and recording planes. Document edits go through `POST /api/document/command`. A grant revoked by the 30 s authz recheck closes `4403`, which is terminal for the tab: `useHostSync` stops reconnecting until reload. A handshake refused at connect is closed before accept, so the browser sees `1006` and the tab retries with capped exponential equal jitter. On accept the server sends a hello `Snapshot` with `document_snapshot(projection="shell")` (same shell `ProjectView` as HTTP `phase=shell`); `Applied` events then carry closed deltas of their named projection against the installed sequence and state token so peer GUI edits and MCP cuts update the timeline without waiting on the poll. The client overlays hydrated `words[]` onto SHELL utterances by source clocks. Guests with `view` subscribe to `WS /api/review/{token}/daw/ws` (session + document + guest-initiated `plane: "progress"`, Presence inbound, sanitized snapshots) via `useGuestSync`; session messages echo the assigned `guest-{token}-…` `client_id` so ghosts do not treat the guest as someone else. `useProjectPoll` remains the 30 s sanity net for writes the socket did not deliver (writes that advance no journal seq, or a watcher read error; guests run it only while their socket is live).

## Progressive project load

First paint is three phases so the DAW grid does not wait on transcript `words[]` or history groups:

1. **Chrome** — as soon as `?project=` (or a guest `view` share) is known, mount `DawProvider` + `DawApp` with `project === null`. Transport, header column, timeline well, inspector, and tabs render as disabled/skeleton chrome. This is **not** the empty-session Start tiles path.
2. **Shell** — whichever arrives first: `GET /api/document/state?phase=shell` (default when `phase` is omitted), or the hello `Snapshot` on `WS /api/host/ws`. Both carry tracks, clips, duration, utterances without `words[]`, comments, and history groups in a sequenced envelope. `project === null` chrome lasts only until that first shell.
3. **Detail** — Host `GET /api/document/state?phase=detail` merges `words[]` and `history.groups` via `mergeProjectPatch` (does **not** call store `hydrate()`, which would clear waveform LRU). Detail requires the captured sequence and state token. A concurrent document change retries hydration against the current authority. A share guest requests DETAIL when the bootstrap flagged `reads_transcript_words` (stored as `shareTranscriptWords`, read through `readsTranscriptWords` in `shareMode.ts`) and `meta.hydration.transcript_words` is false: every review role reads the transcript, a Viewer included (#3786). `GET /api/review/{token}/daw/document/state?phase=detail` then keeps timed `words[]` minus suppressed words, shaped by the sanitizer's `GuestWords` (`NONE`, `READING`, `SELECTABLE`; `guest_words` combines the role and the document-command gate). A Viewer's words (`READING`) carry text, timing, `word_index` and `ignored` only; a Commenter's or Editor's (`SELECTABLE`, the roles `guest_selects_transcript_words` lets submit `EditSelectedRange`) carry the whole word view and keep `unsure_words` on pending edits (#6). A share with no review role reads no words and requests no DETAIL. Selecting a range from the words stays with `rangeEditMode`. Guest deltas are diffed on word-free views, so the client applies them to a word-free basis and re-overlays words by source clocks, refetching DETAIL when a row changed. HTTP `/daw/project?phase=detail` on a share still exists for OpenAPI/tools and is assembled without `words[]` or history (`dump_project_projection(..., audience="guest")`); sanitize then only strips host paths. Guest utterance rows deliberately keep `ignored_word_indices` and `edge_suppressed_word_indices`, which are per-track integer word indices with no text, timings or paths (#633, #752). `guest_transcript` (`gui/mapper.py`) drops `suppressed_only` rows (#758) and suppressed words, whose text guests never see.

`phase=full` is used for host predecessor recovery as well as tests and one-shot tools. Closed projection names (`ViewProjection`, `parse_view_projection`) live in [`projection_types.py`](../src/podcast_mcp/services/document_sync/projection_types.py); HTTP `?phase=` and WS slice assembly still dump via [`gui/assembler.py`](../src/podcast_mcp/gui/assembler.py) (ProjectView seam — see [architecture.md](architecture.md)). `dump_project_projection` builds a view inside a `batch_scope`, and `engines/session_timeline.origin_resolver` resolves each recording once, so a rebuild after an Undo of a large Approve all pays one path resolution per recording, not one per clip (#1535: Daniela Undo 16.9 s, almost all of it this rebuild).

Guest playback prefers **proxy media** when `GET /api/review/{token}/daw/proxy/manifest` returns tracks (`useProxyTransport` + Web Audio clip scheduler). Otherwise `useAudioTransport` streams WAV as before. The proxy scheduler plays each clip at the gain the render gives it: the volume envelope of the lane the clip sits on times the clip's own gain (`gain_db`), its edge fades and its mute regions (`gui/web/src/audio/gainCurve.ts`), pinned to the FFmpeg render by `tests/fixtures/gain_curve/cases.json`, `mute_cases.json` and `fade_curve_cases.json` (`tests/test_gain_curve_fixture.py` renders the others, `tests/test_clip_fade_curves.py` the fade curves, `gainCurve.test.ts` reads them all). An edge fade follows the clip's `fade_in_curve` / `fade_out_curve` (Linear, Equal power `sin(pi x / 2)`, S `(1 - cos(pi x)) / 2`; the fade-out mirrors it), except where a cut or a blended join sets the edge, which stays linear as the render ignores the stored curve there. The render reads the envelope once per 1,024-sample frame, so it lags a steep ramp by up to 21 ms; the preview follows the line exactly. Mute regions play as gain only, with the transcript-ignored words `list_clips` reports as `ignored_word_regions` merged in as the render does: a region's room-tone fill is not in the preview, a clip's off-speaker regions (`off_speaker_mute_regions`) play as the render's automatic gain (silent between their fades, pinned by `automatic_cases.json`; a clip with active Bleed Restore has them baked into its occurrence proxy, restored audio included), a clip plays through the track of the lane it sits on (its staging gain, fader, mute and solo, as the render stages that lane), and a clip with an occurrence proxy already has its mutes baked in (#1649). At a blending crossfade join the scheduler plays each clip on past the seam by half the overlap (borrowed from its recording, `audio/renderClock.ts` `borrowSec`, the same rule as `clips_ops.crossfade_borrow_sec`) and ramps the two over the overlap, as the render does (`timeline_render.placed_track_audio`), so the preview has no dip and later clips stay on the authored clock; only a closed join gap shifts a lane, pinned by `tests/fixtures/render_clock/cases.json`. The client matches the manifest's `project_basis` to the displayed project on the per-track proxy hashes (`render_status.proxy_hashes`, the basis's `render_hashes`) and clip rows (track, origin track, source ids, source and timeline bounds) only (`proxyBasisKey`); `history_head_id` is never compared, so a comment keeps playing. See [host-online-relay.md](host-online-relay.md) § Proxy media.

## Audio transport

Track headers show each track's sample-peak level as the avatar ring (about 8 Hz),
and the track details carry the sample-peak playback meter with the shared dBFS zones
and peak hold. A clip light latches at -1 dBFS for every track on screen, whether or not
its details are open, until **Clear clip light** is
activated, including after Pause, Stop, seeking, or switching responsive shells;
the header shows the lit latch as a danger ring and badge.
In the track inspector the reset is labeled and, with nothing to clear, stays focusable and shows "No clipping to clear."
The reset lives only in the track details, so its target
does not overlap track entry. It resets for a different project or a removed track. These are track-output measurements before the
premix/master, not a loudness or true-peak measurement.

Proxy playback measures after each track's output gain and fades. Local
playback keeps its existing audible player path; silent synchronized track
monitors provide the individual readings while a premix plays. Missing or
loading monitor audio reports an unavailable meter rather than digital silence.
Guests using the premix-only fallback have unavailable per-track readings.
Meter sampling stops with playback. Reduced motion freezes the moving bars and
peak markers while clip detection remains active. The **Volume envelope** layer
still controls automation curves independently of playback meters.

Inspector sheets scroll as one region, including their header, actions, fields,
errors, and footer. On short phone screens, use ordinary
scrolling and the **Expand** icon button to reach complete controls. Focus
transitions reveal the current control within its sheet or desktop inspector;
they do not scroll the page or timeline. Desktop modifier inspectors scroll as
one aside, with fields and errors in natural flow.
See [responsive inspector evidence](https://github.com/calebn/sharecut-studio/pull/963#issuecomment-5998148488) for the text-size profiles
and owner acceptance limits.

A volume-envelope point is edited in the Inspector, not in a workspace. Choose
**Show volume envelope** in the track's sheet (or the eye popover) first;
points cannot change while the layer is hidden. The flat line can be dragged
vertically to set a constant gain without placing a
point. The shown empty line starts at unity and showing it saves nothing.
Dragging it saves equal-level endpoint anchors in one undoable edit. The line
is a focusable slider; arrow keys adjust it by 0.01, and Home/End choose the
range limits. A saved flat line remains adjustable. A shaped curve uses its
individual points. Add a point from the create menu (long press, right click,
or Shift+F10 on the lane); it is selected, and Inspect opens its **Time** and
**Level** Scrub fields. Each field commits once per gesture (a drag, an arrow
step, or a typed value with Enter) with the exact ordered saved baseline and one
undoable change, and the fields are read-only while a save is in flight.
**Remove point** (or **Remove volume envelope** for the last one) and the
Delete or Backspace key on the selected point share the same write. A conflict
stays in the sheet as an alert with **Reload points**; a time already taken
offers **Select the point there**. Editor links edit volume envelopes as the host does; Commenter and Viewer
links see the fields read-only with no Remove. Timeline point drags retain
their local pointer ownership and cancellation behavior.

When the timeline / transport / track headers **or the Transcript tab** are focused (including after selecting transcript text):

| Control | Behavior |
|---------|----------|
| **Space** | Play / pause from the playhead (timeline clock) |
| **← / →** | Nudge playhead ±1s (Shift = ±5s) |
| **Mix** | Stream `artifacts/premix.wav` (full mix). A listen-only mute or solo, or a premix mixed before a volume/mute change (`render_status.premix.stale_vs_mix`), switches to the stem mix so the change is heard before a refresh. |
| **FX** | Stream processed stems (`artifacts/tracks/{id}.wav`) — edits + effects |
| **Per-track levels** | Stem and raw players play each track at its output gain (`gain_db + fader_db`). Media elements can't boost past volume 1, so when a track is boosted above 0 dB every track is lowered by that boost: the balance matches the mix. A saved-muted track's boost doesn't count (the premix leaves it out); solo and listen-only mutes do, so toggling them keeps levels steady. Players are rebuilt only when their sources change (the premix file, or each stem's render hash), so a volume or mute change applies while playing without stopping it, and a later edit to a stale stem still reloads it. |
| **Raw** | Stream source media (`raw/…`) — no FX; output gain in the browser. Playhead stays on the **timeline** clock; each track’s `HTMLAudioElement` seeks via clip `timeline→source` (same dual-clock math as `SessionTimeline` / `clip_timeline_point_to_source`). Mix/FX keep media and playhead aligned (timeline-length stems/premix). |
| **M** | Saved mix mute (`SetTrackMute` writes `track.muted`) for the host and Editors: solid chip; play, the premix (after Refresh) and bounce leave the track out for everyone. A saved mute beats solo. For other guests M is a listen-only mute (dashed chip, `viewerMute`); a saved mute shows to them read-only and M says why. If an editor still has a listen-only mute (from a saved session or a followed guest), M clears it too. Held keys don't repeat M or Shift+S. A saved mute is a mix setting, not access control: guests with `play` can still fetch a muted track's audio. |
| **Shift+S** | Listen-only solo for everyone (AFL-style; never saved, never exported). Tracks your solo silences show a dashed "implied mute" on M — its tooltip reads "Mute (M). Not muted: silent because you soloed another track, and only you hear it that way" — and they go grey like a saved mute, as DAWs grey a muted region: the header row and phone Mix row take `--color-track-muted` through the `mute-implied` class, and the lane through its `data-mute` attribute, clips paint `--color-clip-muted` over their lane colour without the sheen (the label stays white at AA), and the waveform turns grayscale at `--mute-waveform-opacity`. No text fades. Solid = saved in the mix; dashed = only you hear it that way, so a listen-only or implied mute also dashes the row's identity stripe, the phone initials chip and the Mix tile outline, while a saved mute keeps them solid. One source drives every surface: `trackMuteState` through `useTrackMuteState`, mapped to row classes by `MUTE_STATE_ROW_CLASS` and to the lane's `data-mute`. While any track is soloed a **Solo on · Clear solo** button (`track.clearSolo`) sits in the corner above the track headers, at the ruler row, on desktop and tablet (where DAWs put solo-clear, and clear of the transport title); a narrow (tablet) rail stacks "Solo on" over "Clear solo". On phone it sits in the status row above every mode body and at the top of the Mix sheet. Solo turning on or off is announced in the live region ("Solo on. Other tracks are silent for you only." / "Solo off. Every track plays again."). |

Audio is served by `GET /api/audio?path=&kind=premix|stem|raw&track_id=` with HTTP Range support and an `ETag` (mtime+size) so Range revalidation can hit the browser cache. The ShareCut Studio FX transport passes `rerender=true` (plus a cache-bust `v=`) when a track’s stem is stale — e.g. after Track inspector **Bypass** toggles — so A/B audition hears the new chain. While another render holds the render lock, a rerender request serves the existing premix/stem with `X-Sharecut-Render-Busy: 1`, or returns 503 `project_busy` when there is none. The header is an API signal for scripts and agents: the ShareCut Studio transport loads audio through `<audio src>` and does not read response headers. A busy fallback does not rebuild the stem, so its hash stays stale (`stem_is_fresh: false`) and the Mix out of date indicators stay until a later Refresh or rerender succeeds. Generated audition WAVs in `artifacts/play_cache/` are retained for at least one hour after creation or reuse, including during count-based cleanup; cache maintenance and reuse serialize across processes with a cache lock. Last use is the file's atime, so an external reader (Spotlight, a backup or sync agent) also counts as use and can keep an unserved WAV ahead of more recently served ones during count-based cleanup; the file-count caps still bound the cache.

Missing transport media remains a `FileNotFoundError` for host callers and carries a stable refusal code. Guest `GET /api/review/{token}/daw/audio` receives HTTP 404 with `no_mix` and a refresh instruction when the premix is absent, or `file_not_found` with a processed-audio refresh instruction when a stem is absent. Guest copy does not include the host's track identifier or filesystem details.

## Waveforms (pyramid tiles)

Clip waveforms come from a min/max/RMS **peak pyramid** per media file (`.wfpk`, [waveform.md](waveform.md)), which the host builds when tracks are added, re-pointed, ingested or landed, and when stems render. Knobs live in the `waveform` block of [`contracts/timeline-zoom.json`](../contracts/timeline-zoom.json) (generated into `gui/web/src/utils/timelineZoom.generated.ts`).

| Layer | What |
|-------|------|
| **Refs and status** | Each clip draws one media ref: in FX mode the lane's `stem:<id>` while the stem is fresh, otherwise `source:<source_id>` or `track:<origin track>` (`waveform/mediaRef.ts`). `waveform/statusStore.ts` polls `GET /api/waveform/status` once per (project, kind). It backs off 1 → 2 → 4 s while anything is generating, stops otherwise, and polls again at once when the media signature changes (`WaveformStatusSync`, mounted by `TimelineView`) or after a tile 404. |
| **Data** | `waveform/pyramidStore.ts` fetches data tiles (visible before overscan before prefetch, in runs of up to 16), never aborting on zoom or scroll. When a ref becomes ready, it prefetches the coarsest levels. At deep zoom the host adds `(min, max)` PCM blocks (`waveform/pcmStore.ts`); guests stop at pyramid level 0, and raw samples never go to guests. |
| **Render tiles** | `timeline/WaveformLayer.tsx` (memo, primitive props) splits a clip into 512-CSS-px tiles anchored to the media. Tile `k` covers media seconds `[k·512/zoom, (k+1)·512/zoom)`, so moving, trimming or splitting a clip only moves tiles and never re-rasterizes. Tiles mount for the view plus 512 px of overscan per side, from a selector that returns the tile range as a string. Each `canvas.clip-waveform-tile` covers only its part inside the clip, at paint DPR `min(round(dpr·8)/8, 2)`. The layer (`.clip-waveform`) and its snap-tick and mute overlays sit on the clip's border box, so waveform x matches ruler x. Clips narrower than 6 px draw no layer. |
| **Raster** | A worker rasterizes each tile with WebGL2 on an `OffscreenCanvas`, falling back to the CPU after a context loss or without WebGL2. The main thread runs `drawImage`, and turns a CPU tile's transferred pixels into its bitmap (a worker never builds one; see [waveform.md](waveform.md)). A crashed worker is restarted up to twice (re-armed after 64 finished tiles), and layers ask again for the tiles it held; a tile that keeps failing is retired until reload. Once the restarts are spent the backend is `none`. The look is two-tone: the RMS body in the lane's core tint and the peak envelope in its edge tint (`waveformStyle`, `timeline/waveformTheme.ts`). Both backends shade from the same column geometry. `.timeline-area` carries `data-waveform-backend` (`webgl2`, `cpu-worker`, `none`). Bitmaps live in an LRU with a 128 MB budget (48 MB on the phone shell) that calls `close()` on eviction. While a tile's exact bitmap is pending, the nearest-zoom cached bitmap that overlaps it stands in, or a render from a coarser level that is already loaded. **Shift+ArrowUp/Down** or the eye popover's Waveform amplitude field sets amplitude zoom (`view.waveformZoomIn` / `Out`). The eye popover's Waveform scale group picks Auto (dialogue lanes in dB with a −54 dB floor, other roles linear), Linear or Log. The **Waveforms post-fader** chip scales each lane by `gain_db + fader_db`; the clip's own gain is always applied, with the chip off too (the track gain sits behind the chip). The sum is rounded once to 0.5 dB. The scale, amplitude and post-fader flag are remembered per project in this browser (`sharecut.waveformView`, `utils/waveformViewPref.ts`; not a durable store). Past 50 ms per column the peak envelope is dimmed so the RMS body leads. A theme flip re-tints. |
| **Snap overlay** | The quiet wash comes from max-pooled pyramid columns at CSS-px resolution, at 8 px/s and above. Snap ticks come from `GET /api/waveform-snap` (`AnalysisService.waveform_snap_window` → `preview_inaudible_cut` + windowed islands), around the dragged trim edge, else the Alt-click split hover inside the clip, else the paused playhead inside it (`hooks/useSnapTicks.ts`). Ticks still load around the trim edge, the split hover or the paused playhead (magnet for trim, split and body moves), but **draw only while trimming or while Alt shows the split guide**. Ticks show only while the focus stays in the window they were loaded for (same project and track). Each focus loads around its position snapped to a 0.5 s source grid, so a moving trim edge or split hover still gets ticks and refetches only when it crosses a step. They magnetize split and trim, and every drag that uses them follows the Edit corner's Snap toggle (Alt inverts it for one gesture; `snapActive`). The View popover's **Silence shading** chip hides the wash; hiding it doesn't turn snapping off. Pending edges use the same snap ticks when dragged. View-only guests get the wash only. Theme: `--color-waveform-quiet`, `--color-waveform-snap`. |

| Route | Response | Notes |
|-------|----------|-------|
| `GET /api/waveform/status?path=&kind=raw\|stem` | JSON `{format_version, media: {ref: entry}}` | `ready` (key, sample rate, channels, frames, level table) / `generating` / `unavailable` (`no-media`, `decode-failed`, `unsafe-id`); missing pyramids are queued. `no-store` |
| `GET /api/waveform/tiles/{key}?path=&ref=&level=&start=&count=` | octet-stream | Concatenated bins of data tiles `[start, start+count)` (1–16), clipped at the level end; no project parse. Immutable |
| `GET /api/waveform/pcm/{key}?path=&ref=&block=` | octet-stream | Host only: int16 `(min, max)` per frame for one 65,536-frame block; **409** when `key` is not the ref's current key; **503** + `Retry-After` when every compressed-media decode slot is busy. Immutable |

Errors send `Cache-Control: no-store`. Guests get raw-media status and tiles under `/api/review/{token}/daw/waveform/…` ([host-online-relay.md § Guest ShareCut Studio APIs](host-online-relay.md#guest-sharecut-studio-apis-token-scoped)).

Waveforms never block play, seek, edit, scroll, or `add_track`. `TrackLane` shows a "Generating waveform…" hint while any ref its clips draw is generating. It shows "Waveform unavailable" when every ref is known and none has a pyramid. The hint is `.lane-waveform-status`, and the lane carries `data-waveform-status`.

A clip with a timing map (`ClipRow.timing`, steps in source seconds, sent to the host only) draws source media as one `WaveformLayer` per virtual piece (`utils/clipTiming.ts`, `timeline/PieceWaveforms.tsx`), each at its own timeline offset. A hole an inserted step leaves stays blank and a skipped span draws nothing. Past 20 pieces only those within a viewport of the view mount. The clip block spans its timeline length, and mute and clipping spans, snap ticks and gain dips follow the pieces. A `stem:` ref stays one layer because the stem is rendered on the timeline clock (`render_track_from_timeline` expands timed clips to their pieces and places them, holes included), and a clip with no timing keeps its single layer. Seek and playhead follow the pieces, but browser audio scheduling (`audio/proxyMath.ts`) stays linear until the preview schedule is made step-aware, so a timed clip's heard audio and playhead disagree after its first step in the browser.

**Budgets (CI):** Vitest covers the tile geometry, envelope reductions, shading, stores and layer (`src/waveform/*.test.ts`, `timeline/WaveformLayer.test.tsx`, and `timeline/WaveformLayer.raster.test.tsx` (the real raster client with two layers: drop and crash re-requests)). Playwright `e2e/waveform.spec.ts` checks that tiles come from `/api/waveform/tiles/` (at most 384 KiB per response). It also checks that no `/api/audio` window is requested, that tile canvases are painted and that the tile count stays within the view plus overscan. It also crashes the raster worker through the E2E hook and checks that a new one renders and paints tiles. On Chromium it expects `data-waveform-backend="webgl2"` and `rasterParity() ≤ 2/255`. Guests draw through the share route with no PCM. The compat matrix accepts `webgl2` or `cpu-worker`, and `e2e-compat/deep-zoom.spec.ts` checks ruler, tile, envelope and scroll geometry at the one-hour ceiling (15 M px) on Chromium and WebKit.

Pending **Current / Suggested / A/B** audition plays the server's rendered pending preview for every pending edit, the same render as `play_pending_preview_tool` / `podcast play pending-preview`. Current is the project as it is around the edit. Suggested is the edit approved on a snapshot (ripple, `replace_gap_sec` paced pad, fades, mute), so the editor hears what approving ships. Both mix their window from per-track segment renders at the headroom trim the premix gets for the current mix, so a fader or mute change re-measures the mix peak instead of re-mixing the premix ([daw-editing.md § Listen-first pending preview](daw-editing.md#listen-first-pending-preview)). **A/B** is one WAV: Current, ~0.4s gap, then Suggested. The Action bar's Hear before and Hear after, the pending inspector footer (on a sheet with no bar) and the Review Queue's A/B all go through `audio/pendingPreview.ts`: the host fetches `GET /api/pending-preview`, a share guest with `play` the token route `GET /api/review/{token}/daw/pending-preview` (agent twin: `guest_pending_preview`; relative URLs, not host speakers). The WAV plays as a source preview owned by `pending:{edit_id}` until its length (read from the WAV header) runs out. Suggested plays a cut the cut-position or join checks hold (`acoustic_edge`, `peer_speech`, `speaker_bleed`) as approving it anyway would give, on the private snapshot, so the editor can hear it first; pause-policy and project-integrity holds still make it unavailable. A host approval or Suggested preview held by changed cut scope returns HTTP 400 with `X-Sharecut-Error-Code: cut_scope_changed` and names the held cut. Source geometry also checks operation lanes: parked MUSIC holds as `operation_scope`, while voiced parked media still needs fresh speech evidence. Suggested uses its private snapshot. Saved approval adds its unchanged-batch assurance only after history and registered editable/render recovery complete; an uncertified restore preserves the original failure and forces authoritative workspace reload. The pending view's `suggest_reason` keeps Suggested and A/B focusable and unavailable (`aria-disabled`, no action on click, Enter or Space), with its reason in a visible note beside them: splits have no Suggested side, and an edit off the current timeline (or a stale exact range) cannot play at all. Mutes and track punches render Suggested.

Continuous playhead while playing must not emit durable `SetPlayhead` Applied events (that re-seeks the browser audio and stutters). Followers omit `playhead_sec` / `is_playing` from that snapshot.

**Transport authority (Figma-like):** each DAW tab owns its own play/pause clock. **First Snapshot:** the DAW applies agent transport from the connect snapshot **before** recording `last_command_id` as applied (see `gui/web/src/session/dedupe.ts`), so an in-flight agent play still seeks/highlights when a tab opens mid-command.

Keep the viewer pointed at the same `episode.sharecut`.

## Review stage: Find more and Cut all

The Queue header's **Find more** button (host only) reruns suggestion finding through `POST /api/pipeline/run` with `only_step: analyze_fillers_pauses` and the project's saved **How tight** (`tighten.intensity`, set in Prepare Cleanup; Review has no intensity control). By time has no group headers, so there is no **Cut all N** and `Shift+Enter` does nothing; J/K, the next item after a decision and the "N of M" count follow the order shown. The "saves N s" figure in the progress line, the batch rows and the verb bar is the timeline shortening, the union of the removed ranges: two edits over the same moment, such as the same cut on two tracks, count once, and a mute, track-scope or exact-range cut leaves the timeline length alone and counts none, and an item that carries no ranges counts its own seconds.

A group's **Cut all N** hides the group at once, so the host owns the running state: the Queue shows "Cutting N…" in its place until the request ends. The host reports no count for this command, so the row is indeterminate (elapsed time after 2 s, no percent), and the decision ends with one Undo for the whole group. Risky cuts join the group; unsure words, blocked cuts and Keep or Lower items stay out, and a cut the server holds at approve time (another speaker talking over it, or an audio check) returns to the queue as held ([daw-editing.md § Tighten review](daw-editing.md#tighten-review)).

Any change that leaves the mix behind (opening a project with no mix, an edit, a gain, mute or FX change, an alignment move) starts a rebuild on its own in the host's Studio (`useAutoRefreshMix`), 1.5 s after the last change, so a burst of edits rebuilds once. It is the same single-flight `render.refreshMix` the manual command runs: it waits for a running rebuild or pipeline slot job, then rebuilds for the newer change, and it does not retry a state it already tried and could not clear. Playback keeps using live per-track audio or the last good mix while it runs, and the transport pill reads **Updating mix…** while it does. A successful automatic rebuild is silent; a failed one announces the failure as the manual command does. The palette command **Refresh mix** stays as "update now" and is never needed. Until the project has loaded, the pill reads **Checking mix…**, never **Mix up to date**. Docs Editors on a share keep the manual **Refresh** (their host's Studio rebuilds when it is open), and a stale transcript alone does not trigger it. A browser preference (`localStorage` `sharecut.autoMix` = `off`) pauses the automatic rebuild; the e2e suite sets it so lifecycle audits that assert an untouched project file are not written to by a rebuild.

**Mix out of date UX:** The Player bar mix ring (**Mix out of date**) (hover/focus) highlights **cause regions** from `render.invalidations[]` (timeline bands for cuts/clips; header chips + light lane edge for whole-track FX/gain/mute). Premix → Mix audition cue; reconcile → Stage bar **Reconcile** badge. Host or Docs Editor may **click** the pill or run **Refresh mix** from the palette (`render.refreshMix`) to rebuild stems/premix (clears per-track invalidations when stems go fresh). The wide-bar pill is one pill for everyone, which keeps the transport within 1280px: **Mix out of date** (Docs Editors on a share read **· Refresh** after it; the host's mix updates on its own and the pill reads **Updating mix…** while it does), or **No mix yet** when nothing is rendered, whether it was never rendered or a failed render left none (the guest wording has no Refresh, since a guest cannot take it); Full mix's tooltip and description add that Full mix is silent until the mix is refreshed; the refresh action is in its tooltip, its accessible name (…“Refresh mix.”), the palette, and the collapsed Menu's **Mix out of date · Refresh** item. Viewers and Commenters get the same hover highlight only, and their pill's name omits “Refresh mix”. Refresh start/result is announced via a polite StatusBar live region (`statusAnnouncement`). Invalidations are diagnostic (what changed since last fresh stem); stems remain whole-artifact.

A project with no source media or timeline clips stays **Mix up to date** despite empty-track creation invalidations; it does not show an audio error for the absent premix. The project view includes a non-sensitive `has_source_audio` track flag so guest shares still identify playable media after local media paths are redacted, including when source duration is unknown. Opening a different project resets per-project transport and error state; refreshing the same project preserves it. From fit mode they step from the drawn (fitted) height, `drawnLaneHeightPx`, so Increase never shrinks the lanes and Decrease never grows them; from fixed mode they step the saved fixed height. `timeline/timelineMetrics.ts` `resolveLaneHeight({ mode, fixedPx, availablePx, trackCount, fit })` picks the lane height for the current mode (`fitLaneHeight` only runs in fit mode), bounded by `fit` (`LaneFit`): `pointer` keeps it as is, `touch` (a coarse pointer or the phone's fixed playhead) raises it to 104px, and `touchShort` (a screen at most 40rem tall whose primary pointer is coarse, `hooks/useShortTouchScreen.ts`; the capability, not the last pointer used, so a first touch never resizes lanes) uses the compact lane, `shortTouchFloorPx` (72px, or 3.25rem when large text grows the 2.75rem identity chip past it), for any fixed height, and fit mode never fills below it (#1077). On a short touch screen `markerLaneHeight` drops the empty lane's quiet row. Below `COMPACT_LANE_HEIGHT` (104px) `.timeline-area` carries `data-lane-density="compact"` and each desktop track header puts its name and M/S on one row with the **Out** readout under them, so nothing is clipped at 72px; the fixed fallback sits exactly at that floor, so it shows the full header layout, while a dense Fit session draws 72px lanes with the compact header. One `ResizeObserver` (`ui/useResizeObserver`) on `.timeline-scroll` and its header column triggers both fits (the time viewport, `clientWidth` minus the headers → fit zoom, refit only for a new width or session length; height → lane height in fit mode only; in fixed mode the observer records the height but skips the refit, and a mode or fixed-height change re-resolves without waiting for a resize), measured first in a layout effect so the first frame is already fitted; the timeline re-renders only when the whole-px lane height changes, and desktop `.timeline-scroll` keeps a vertical scrollbar present so the fit cannot oscillate as tracks gain or lose vertical overflow. It uses the default scrollbar gutter so short lanes can reach the horizontal end; phone fixed-playhead mode scrolls vertically only when needed. The ruler and marker lane stay pinned at the top of `.timeline-scroll` while track lanes scroll vertically. Both pan horizontally with the track content; matching track-header chrome stays pinned above the header column. The marker lane is one `MARKER_ROW_HEIGHT` (24px) system marker lane (chapters, social clips and comments together; overlapping markers fold into a `+N` chip) plus, when a recording has clipping flags, a `clipping` row under it (flags from `ClipRow.clipping_regions`, one per region per track; click selects the track and seeks); an empty lane is one quiet row; `TimelineView` computes the rows once and hands them to `LiveMarkerLane` (`timeline/MarkerLaneHost.tsx`). Ruler, marker-row, lane and marker-lane heights are CSS px from `gui/web/src/utils/layout.ts`: `TimelineView` sets `--ruler-height`, `--marker-row-height`, `--lane-height` and `--marker-lane-height` on `.timeline-area` and timeline.css reads them, so rows line up with the code and the header chrome at any root font size. Overlays and headers read the live heights from `useTimelineMetrics()`, so the header column renders inside `TimelineView` (`headerSlot`) whenever a timeline is drawn, including a zero-track project viewed without ingest rights. Only the loading skeleton (which reserves the same default ruler + marker room as the header chrome) and the host's empty-session drop target keep it outside. While a clip move, trim, fade, roll or envelope drag is active, the drawn geometry (lane height, marker rows) is held (`useHoldTimelineMetrics`), so a collaborator's update — or a mode/height change — cannot move lanes under the pointer; it applies on release. A clip move drops on the lane its ghost showed rather than hit-testing again at pointer-up.

**State composition:** `gui/web/src/state/dawStore.ts` composes project, transport, presence, and UI slices into one Zustand store, wrapped in `state/writeBatch.ts`'s `dawWrites.middleware` (exported as `batchDawWrites`): every `set()` call made inside a `batchDawWrites(fn)` folds into one pending state instead of writing straight through, `get()`/`getState()` inside `fn` see the pending writes, and listeners fire once at the outermost batch's exit. It must stay the store's only middleware, since it swaps `setState`/`getState` in place. `hydrate()` keeps project-switch resets and zoom reclamping in one update; `applyAgentSession()` likewise updates the session, transport, and selection together. The mounted timeline/lanes DOM nodes and fixed-playhead lead pad are kept in `state/timelineViewportRegistry.ts` rather than reactive store state. `TimelineView` clears the registered elements on unmount; its `useFixedPlayheadScroll` hook clears the lead and clamps negative logical scroll to zero. Presence and zoom measure the registered nodes when needed.

**Inbound sync frames:** `useHostSync` owns the host session, document and recording planes. `useGuestSync` owns guest delivery. Both use `sync/inboundQueue.ts` for ordered state work and reject retired socket lifetimes. Clock sampling and the host's own ViewerState echo deadline remain at receipt. DAW writes batch once per animation frame, with a timeout while hidden. Full presence rosters can coalesce; durable updates and incremental presence patches cannot. Host recording snapshots commit the monitor roster synchronously before subsequent signals. Own-client HTTP document results flush prior inbound work first. `FakeWebSocket.emit()` delivers and flushes; `deliver()` leaves work queued for ordering tests.

Use module-scoped `pickDaw("field", ...)` selectors for plain field sets. Governance checks their literal keys against the hot-field allowlist and rejects computed arguments. Use a custom `useDaw` selector for conditional projections of store values; build derived arrays and objects with `useMemo` outside selectors. The plain timeline and lane components are exported as `*View`; lane callbacks take the track id first and clip callbacks the clip id first, each one stable (`utils/useStableCallback.ts`), and idle fallbacks share the frozen constants in `utils/empty.ts`. `useStableCallback` updates its implementation during commit, before layout effects. Call it from a handler or effect. The source test in `utils/useStableCallback.test.tsx` rejects supported direct calls during the owning function's eager evaluation. Babel scope bindings resolve lexical shadows. Typed expression wrappers, synchronous inline IIFEs, React's `useMemo`, lazy `useState`, and `useReducer` initializers are covered. Method creation and instance fields are deferred, while computed keys, heritage, static fields, and static blocks are eager. Parameter defaults have bounded syntactic argument handling. The check does not follow aliases, named helpers, child props, dynamic member names, or async and generator execution. A passing test covers local forms only. See the [frontend testing contract](../gui/web/README.md#testing) for parameter limits and fixtures. The hook does not throw at runtime. Its runtime tests retain the old committed callback through a suspended transition and expose the latest value after commit.

The transcript highlight index sorts utterance and word activity bounds by
timeline start and stores the running maximum end. Two binary searches prune the
candidate window on each tick, including backward seeks. Results keep transcript
row order and use the shared active predicates for overlapping speakers, split
spans, and instant words. A long overlapping row can still widen that window.

`ProjectView.comments` lists all timeline comments for markers + the Review queue.

Pending edits and combined transcript utterances in `/api/project` include **dual clocks** (`source_*` / `start`·`end` plus mapped `timeline_*` / `timeline_spans` / `mappable`) via `SessionTimeline` — the UI must not plot raw source times on the timeline ruler or seek the playhead with source clocks after cuts. Utterances also carry `words[]` (per-track tokens including suppressed, with `word_index` / `confidence` / `suppressed` / `suspect_hallucination` / `audibility_locked` and timeline clocks) for seek and **Correct**-mode selection; `audibility_locked` (#768/#781) marks a word whose `suppressed` state was set directly by a person or agent decision rather than a heuristic pass — the transcript view shows a lock affordance on these words so a reviewer can tell a pinned decision from a heuristic suggestion; on-disk `combined.json` is unchanged.

Transcript word identity is `(track_id, source_id, word_index)`. `source_id: null` identifies the track's primary recording; a selected extra take keeps its own source ID even when its word index and source time match another take. Selection, presence anchors, Correct/Ignore/Restore and timing targets carry this identity through the document command. In UI command arguments, an omitted `sourceId` means use the active transcript selection; `sourceId: null` explicitly targets the primary recording. A row-level Restore always carries the source identity of its row. The UI never picks a transcript by matching text or time. When source transcripts exist, `ensure_combined_transcript` rebuilds the combined utterance projection from those transcripts at the existing read boundary. Word corrections, suppression, timing edits and `user_edited` state remain on each source transcript; the projection is not the edit store. A project with no source transcripts may still expose its saved combined transcript, without inferring a missing source ID from row contents.

`merge_transcripts` drops a suppressed word from `combined.json` entirely when it falls before, after, or between the non-suppressed utterance windows on its track (an utterance's first or last word, or a suppressed run between two utterances) — that word has no `[start, end)` window of its own to live in. `gui/mapper.py`'s `_edge_suppressed_word_indices` attaches each such word to exactly one same-track utterance (the nearest by source-time gap, ties to the earlier one) purely as a view concern: `combined.json` and `merge_transcripts` are unchanged, and the word keeps its own timeline clocks and `word_index`, so Correct and Unsuppress work on it like any other chip (#752). A row's own word listing, its `ignored_word_indices` and this coverage check share one predicate (`_covered_word_ordinals`), and a zero-length utterance window (which `merge_transcripts` emits for a lone zero-duration word) is padded like a zero-length word (`word_source_span`), both for that coverage and for the row's own `timeline_*` / `timeline_spans` / `mappable` mapping. So a zero-length row on kept audio is mappable and shows in the default transcript view, and a suppressed word straddling that window is listed on that row, not dropped. Each SHELL and DETAIL utterance row lists the words attached this way in `edge_suppressed_word_indices` (ascending, only when non-empty), so the client's SHELL word overlay refetches DETAIL when a row's attachment changes. Both projections also carry `locked_word_indices` for locked words in the row, including attached edge words and words in `suppressed_only` rows. A lock-only change invalidates the client word overlay so undo and redo reload the current lock state. Attachment is by source time only: a word nearest a cut-away (`mappable: false`) utterance attaches to that row and keeps its own timeline clocks, but, like the rest of the row, shows only when cut-away lines are shown.

A track whose words are **all** suppressed produces no utterance in `combined.json` at all, so it has no row to attach a chip to via `_edge_suppressed_word_indices`. `gui/mapper.py`'s `_suppressed_only_rows` fills that gap purely as a view concern: it adds one synthetic row per gap-run on that track — the same 0.8s split `merge_transcripts` uses (shared via `engines/utterance_runs.py`) — sorted into the transcript by source start (stable, so input rows win ties; runs from several all-suppressed tracks interleave by time), so a bleed track's words spread across the episode instead of landing in one giant turn at the top. `words[]` on such a row are the run's suppressed chips and `text` is their joined text (the same format a real combined utterance would carry), which keeps the SHELL word overlay's text guard meaningful for these rows too. The row also carries `ignored_word_indices` when relevant, but never `edge_suppressed_word_indices` (its words are already all attached to it). A track with any unsuppressed word, or one that already has a row in the input combined transcript, gets no synthetic rows; `combined.json` and export are unchanged either way. Every synthetic row carries `suppressed_only: true`, which ShareCut Studio renders dimmed and keeps out of the active highlight, follow scrolling, the low-confidence walkthrough and the toolbar utterance count (still counted as cut-away when unmapped, so **Show cut away** can reveal them). For a selected suppressed word, the word inspector offers **Unsuppress**. `findTranscriptWord` scans `utterance.words` regardless of the row's flag; after an Unsuppress, the rest of that gap-run's words become ordinary edge-suppressed chips on the real utterance that then exists (#752, #758).

`transcript.utterances[].words[].unsure` and `pending_edits[].unsure_words` / `unsure_count` are the server's verdict on `analysis.unsure_word_confidence`; the server owns the threshold; the client's own constant in `transcript/lowConfidence.ts` is replaced when the Review lane wires the flag ([gui-integration.md § Unsure words](gui-integration.md#unsure-words)).

`pending_edits[].author` is `share:` plus the authoring share's opaque id, or `null` for host and agent edits; guests compare it with their bootstrap `author` to offer Retime only on their own suggestions ([share-tokens.md § Roles and general access](share-tokens.md#roles-and-general-access)).

`pending_edits[].join_risk` is optional view metadata for tighten proposals (`filler:` / `pause:` / `repetition:` / `restart:`). It maps propose-time reason suffixes (`:risky`, `:join_review`) through `gui/mapper.py` — **not** a live `TimelineService.join_quality` sweep on every ProjectView snapshot. Verdicts are `review` when those suffixes are present; otherwise the field is `null`. Use `join_quality_tool` for a per-decision live score. `pending_edits[].harsh` is true only for that same join risk; `review_required` alone (unsure words, acoustic holds, held pauses) does not make a hit harsh; the Review Queue reads it as its top risk flag. `pending_edits[].kind` and `sound_kind` are the server's queue group and raw sound (see [gui-integration.md § Pending edit `kind`](gui-integration.md#pending-edit-kind)); the Review Queue groups on them rather than on the reason prefix. `pending_edits[].why` is a plain sentence to display when present. A `null` value means the card omits the line. See [Pending edit `why`](gui-integration.md#pending-edit-why) for the author gate, reason parsing, provenance limits, and pause-gap meaning. `pending_edits[].harsh` (`edits/tighten_hits.is_harsh_tighten_hit`) no longer gates a bulk apply: Apply suggested actions (`ApplySuggestedActions`, `apply_suggested_actions_tool`) gives each hit its suggested action from `edits/cut_policy.py`.

**Transcript display is non-destructive:** displaying or hiding retained cut-away (`mappable === false`) utterances does not alter on-disk `combined.json` or its source clocks. The DAW hides them by default and can show them dimmed (non-seekable); export already omits unmapped lines. Follow/active/seek use **timeline spans only** (no fallback to source `start`/`end`).

Boundary word previews combine active cutaway words with `Transcript.archived_words` retained by cuts. Adjacent clips must resolve to the same source transcript; a join between unrelated recordings does not borrow same-timestamp words. All cutaway preview references carry their source identity and a negative `word_index`, which is not an active transcript mutation target. A roll or trim that restores the complete word span returns that word and its metadata to the active transcript before rebuilding combined text. Partial words remain archived. Older cuts with no stored archive still require History recovery. Precision-boundary limits use each clip's selected recording duration and compare neighboring source positions when both clips identify the same recording on a track, or when different source identities resolve to the same media path (including an explicit source that aliases primary media). The same source identity needs no media-path lookup for a source-clock contraction. A recording with no known duration cannot expand past its current out-point. A preview token covers the selected track's render state, selected media revisions, and source transcript metadata that a proposed expansion might restore. A stale Apply conflicts before history or project changes. See [episode-format-v2.md](episode-format-v2.md#transcripts-canonical-in-project-file).

The host `POST /api/boundary/context` and edit-share `POST /api/review/{token}/daw/boundary/context` accept a typed trim or roll target plus the clip geometry the editor displays. They return finite legal bounds and reject a changed visible clip with 409. A roll target whose clips have a gap between them is refused with HTTP 400, `X-Sharecut-Error-Code: roll_needs_abutting_clips` and plain copy as the detail (a `CodedValueError`; `bad_request_error` in `gui/routes/deps.py` sends the code on every route that maps one this way, so the drag error and the precision dialog show that text). Only the host can use `POST /api/boundary/audition`: it checks that context token, copies the saved project, and applies the existing timeline operation to the copy. `PlayService` transiently renders each complete affected track, applies its staging gain, fader and whole-track peak ceiling, then crops separate current and proposed playback windows. These WAVs include that track's edits, selected recordings, joins, fades and FX; they are labelled as track audio rather than the full episode mix. Bounded `artifacts/play_cache/` entries hold only the cropped exact-geometry windows; temporary full renders are removed after extraction. A host-authorized `GET /api/boundary/audition/{id}/{side}` serves only issued entries with HTTP Range support and rechecks the preview token. Rendered drafts do not write the project, history, document journal, stems or premix. Every `TrimClipEdge` and `RollClipJoin` command requires `expected_token`, checked within the workspace transaction before mutation or history. Quick drags obtain it from context using their captured visible geometry; CLI and MCP trim obtain it within their project transaction. An unchanged precision Apply leaves the saved project and history untouched, though its document command receives a normal journal acknowledgment.

**Applied edits:** legacy `editorial.edit_log` rows missing `timeline_*` are remapped for the view from source clocks (first `track_ids` entry) in the assembler — view-only; the on-disk edit log is not rewritten. The lane's applied-edit ticks do not use `timeline_*` at all (#527): they come from `params.per_track_source` (`ripple_delete`/`punch_delete`/`approve_edits`/`apply_prefix_edits`), `params.split_source_by_track` (`split_clips_at`/`approve_split`), or the record's own `source_start`/`source_end`, projected through the track's current clips.

`ProjectView` also includes `social_clips` (timeline-clock candidates from `social.clip_candidates`) and `envelopes` for lane-level volume curves.

Implementation: [`src/podcast_mcp/gui/`](../src/podcast_mcp/gui/) (`server.py` wires routers; handlers live in `gui/routes/`), frontend [`gui/web/`](../gui/web/) (Zustand slices under `gui/web/src/state/`, session dedupe in `gui/web/src/session/`).

Every review-link role holds `view`, so `/r/{token}` always opens ShareCut Studio. A review share without `view` (only a hand-built `ShareService.create(capabilities=…)` call makes one) has no page: bootstrap succeeds and the app shows "This link doesn't open anything" with the next step beneath it, "Ask the person who sent it for a new link." ## Frontend internals

Module ownership notes moved from [architecture.md](architecture.md).

Playback meter sources live under `gui/web/src/audio/`. Transports bind one
runtime source through `playbackMeterSource.ts`; track meter leaves subscribe
without sending frame readings through the project store. `channelPeakTap.ts`
measures channels independently so opposite-polarity stereo cannot cancel.
`ProxyEngine` owns its post-gain taps. It schedules sources for a horizon
ahead of the playhead, two minutes at first, and extends it from the audio
clock. A silent sentinel node fires `ended` when under 45 s of sound remain,
so a guest hears the whole episode from one Play even when the page is
throttled and timers and frames stop. The episode ends at the later of the
project's timeline duration and its last clip end, as in the render. There the
engine pauses itself and reports the end. The transport parks the playhead
there (an audition that reaches the end also clears its range), and Play again
starts from 0. A snapshot that moves the end reschedules like a clip
change. `hostPlaybackMeterMonitor.ts` fetches
processed PCM16 stems and validated raw PCM16 recordings through finite byte
ranges checked against each asset's ETag. Compatible source sample grids share
bounded native WAV readers with separate per-track channel taps and gains. Each
asset retains its own byte identity;
a failed member does not disable healthy tracks. The monitor owns the current and
next windows, aborts obsolete requests and revokes retired local URLs. Readings
remain unavailable until native progress, tap warmup and current-position checks
pass. Unsupported raw recording formats retain full-resource native decoding.
Both paths follow the audible HTMLAudio transport without changing premix playback.
Inactive
playback retires the private meter context; the transport keeps its close barrier
across monitor replacements and waits for close completion before opening another.
Shared metering math and the reference-counted frame scheduler supply peak hold
and clip detection. Transport cleanup owns audio
resources; the meter leaf owns presentation. `playbackClipLatches.ts` retains
clearable clip state across responsive shell remounts, scoped to the current
project and surviving tracks.

Timeline horizontal scroll policy lives in `gui/web/src/timeline/useFixedPlayheadScroll.ts`.
The parent hook owns lead lifecycle, committed canvas sizing, DOM scroll echoes,
and pointer zoom gating. Its immutable render binding connects the canonical
scroller and geometry to separate `TimelineScrollSync` and `FixedPlayheadRecenter`
children. Hot scroll and transport subscriptions belong to those children,
outside the parent hook, so frame updates stay outside arrangement rendering.
The children mount after the scroller ref attaches and reconcile when measured
columns change. Scroll events with live columns that differ from the committed
mapping wait for that reconciliation, preserving transport and Follow intent.
Store scroll describes the applied viewport. When a responsive layout cannot
represent the requested pan, the ephemeral viewport registry retains a scoped
requested/applied projection until it can restore the request or navigation
invalidates it. Recording preview classification keeps its original line
geometry across phone and ordinary timeline mounts.
`TimelineView` retains shared column measurement, gesture attachment, and desktop
region reveal. Vertical geometry remains in `timelineMetrics.ts`. See
[GUI render isolation](gui-viewer.md#gui-viewer).

Frontend app feedback stays in `feedback/FeedbackToast` and `ui/Toast`.
Compact shell composition registers an optional DOM host through `DawApp`.
`BottomSheet` renders the supplied flow slot first inside its body. Compact
sheets keep chrome outside that one scroller and remove nested inspector
scrolling. Feedback presentation observes actual card intersection with the
viewport and clipping ancestors in both compact and floating hosts. `Toast` owns the remaining visible lifetime
and pauses it while clipped. A stable portal container moves the single card
between floating and compact flow presentations without remounting its timer
or guarded Undo. Its native action carries the single feedback focus intent.
Sheet entry focus (`useDialogModal`) and the volume-envelope view's first-entry
focus yield to that valid intent through the generic `ui/focusHold` seam, which
the feedback module registers; no other inspector view defers entry focus.
The person's own navigation clears the intent; a selection adopted from the agent or a followed leader
(`adoptRemoteSelection`, `remoteSelectionRevision`) does not. No other client's selection reaches a tab, and an agent's applies once, when it sets it (D-tabs-keep-own-selection). The current compact Close supplies the existing Toast
return-focus ref, validated when this tab's own undo removes or disables the
focused action, including when a peer edit removes it. `ui/modalGate` keeps a
modal above every non-modal, and ranks remount-stable peek sheets below later
non-modals, so a sheet opened or remounted behind a modal or
popover takes neither Escape nor entry focus; it takes entry focus when the
inner overlay closes without a usable return target. A remounted inspector
does not steal focus from a docked Cut anyway button. A new sheet still takes
Close after deferred envelope first-entry. The keymap skips Escape
commands while any overlay is open (`overlayOpen()` skips
`edit.clearSelection`). A clip fade Scrub field's Escape stops propagation only
while a drag or typed edit is open, so cancelling it leaves the sheet
open. Idle Escape on a fade field still dismisses the sheet. `Toast` re-reads
`document.activeElement` after each commit, so a host move that detaches a
focused action without a blur resumes its timer. Store announcements and command authority
remain unchanged. See [mobile feedback](gui-mobile.md#feedback-toast).

Frontend pointer dispatch policy lives in `gui/web/src/commands/pointer.ts`.
`gui/web/src/commands/seek.ts` routes transport seeks through that pointer
adapter and returns the command result so Listen, timeline, and DAW WebMCP share
the same seek path.
`runPointerCommand` dispatches without keyboard `when` gates and returns `void`;
`executePointerCommand` exposes the same dispatch promise for completion and
result handling. Keyboard input evaluates its gates in the keymap listener,
while WebMCP `play_pause` returns the original `execute` result in its agent adapter.
Its reply is `{ status: "ok" }` on success, `{ status: "disabled", reason }` on
refusal, or `{ status: "unknown" }` when the command is unavailable. Disabled
replies preserve command metadata such as `announced`, and command errors reject
the tool promise unchanged. WebMCP seek awaits the shared seek helper.
Configurable `CommandButton` gates remain in the UI
bridge. See [the frontend command adapters](../gui/web/README.md#api-adapters).
